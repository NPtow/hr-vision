# Автоматическое сравнение вакансий · приёмка

Это исходная матрица первой приёмки автоматизации; результаты проверок и их границы записаны в `TEST-RESULTS.md`. Текущая формула — в `RUNTIME-MATH.md`. В выпуске 1.2.0 применяется согласованная политика `tanh-higher-zero-v3`: неизвестная важность даёт эффективный вес 0 и исключает только этот навык. Исходные ответы модели сохраняются. Смена версии политики автоматически возобновляет ранее остановленные сравнения.

Baseline: a567c7bac4bbc631050fd73cd3fee81c32b67554. Целевая среда: существующий YC, HR API + recommendations + Верстак. Пользователь подтвердил 0–100 и универсальный автоматический расчёт для каждой вакансии. Ручной прогон или исследование текущей вакансии после выпуска запрещены последним уточнением; меняем и выкладываем код.

Сохраняется разделение: assessment-core оценивает весь корпус кандидата; vacancy-profile — снимок вакансии; recommendations считает без модели; HR владеет авторизацией, текущими версиями и фоновым запуском; UI читает результат. Никаких автоматических приглашений, публикаций или ASR.

Нормирование текущего индекса: `score_points = 50 * (score + 1)`; null остаётся null. Исходный score и исходные ответы сохраняются. Одинаковые данные и политика не вызывают повторную оценку JEV. Известное требование использует `tanh(l-r)`; отсутствующее требование реализует указание пользователя «чем выше, тем лучше» через `2*(position-1)/(N-1)-1`. Для пяти уровней это 0/25/50/75/100 до учёта важности. Линейное расстояние между уровнями — явное правило реализации, а не эмпирическая калибровка. Требование остаётся null; в v3 неизвестная важность исключает навык с весом 0, а не останавливает весь расчёт.

Фоновая обработка: все доступные активные вакансии; полный пул кандидатов с готовыми записью и транскриптом HR-интервью; явный отказ при >1000, без усечения. Состояние и backoff в HR SQLite, один runtime-владелец, без HTTP под общим DB lock. Сравнение считается устаревшим при смене вакансии, профиля, материалов, оценки, фактов, политики или состава пула. Открытие UI не запускает модель.

Синтетический профиль первой приёмки: 3 вакансии и минимум 7 готовых кандидатов. Цель: изменение уже готовых входов обнаруживается за 60 с в штатном режиме; длительность JEV обособлена. Проверяем алгоритм и жизненный цикл в изоляции, выпуск — штатными защитами и проверкой здоровья. Проверка карточек и чисел на реальных вакансиях не входит в этот выпуск по просьбе пользователя.

Предыдущее ограничение protected build-runner (VPN fake-DNS) сохраняется как принятый пользователем пробел: обычная разработка и независимая алгоритмическая изоляция не называются полным build/seal/verify PASS.

Диагностика: статус по вакансии в ответе recommendations, состояние runtime в selection/status. Обновление HR/UI — существующий защищённый CI receiver; recommendations — существующая независимая упаковка и guarded upgrade. Результаты привязываются к commit/service version. Старый артефакт сохраняется; новый score_points добавляется без удаления score и прежних результатов.
