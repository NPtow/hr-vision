# Подключение кабинета к ядру — 26 октября 2026

Обвязка применяется ко всем согласованным участиям кандидатов из общего каталога
Верстака. Ни списков людей в коде, ни ручной миграции отдельных карточек.
Рекомендация и одобрение принадлежат существующему процессу; сервис не создаёт
кандидатов, приглашений, согласий и не вычисляет итоговый балл вакансии.

Вход: текущий `full-corpus-level-choice-v1`, текущий
`vacancy-level-importance-v1`, разрешённые реплики основного интервью.
Выход: существующее представление Орбиты, до семи оценённых параметров с
положительной известной важностью и вероятностью нехватки данных не выше 0.5.
Порядок — важность вакансии, затем превышение требуемого уровня, затем каталог.
Баллы — выбранные ядром уровни; неизвестность не заменяется нулём.
Цитаты не меняют оценку. Одинаковое интервью и определения параметров используют
один сохранённый подбор цитат, даже когда поменялись вероятности или вакансия.

Новое согласованное участие впервые публикуется после подготовки. Уже доступный
кандидат остаётся в подборке при обновлении или ошибке. Параметры обновляются
единым сохранённым результатом; прежний результат доступен до замены. Техническая
ошибка остаётся задачей с ручным повтором, ожидание ядра не является ошибкой.
Авторизация и отозванное согласие продолжают проверяться владельцем кабинета.

## Приёмка

| Сценарий | Ожидаемое поведение | Свидетельство |
|---|---|---|
| Общий каталог | Все подходящие участия обнаруживаются автоматически, чужие/неодобренные не публикуются | Интеграционный тест HR |
| Контракт | Текущие результаты ядра и вакансии читаются без запуска оценщика | Контрактный тест и сохранённые реальные входы |
| Выбор параметров | До 7, приоритет вакансии, исходные уровни; нет общего балла | Тест сервиса |
| Два потребителя | Подборка и Орбита получают один revisionId и значения | Интеграционный тест маршрута |
| Новая оценка | Уже опубликованный кандидат остаётся; обе проекции меняются вместе | Интеграционный тест HR |
| Переиспользование | Новый run или вакансия при тех же репликах не вызывают модель повторно | Тест процесса/SQLite |
| Ожидание и ошибка | Ожидание завершается автоматически, технический сбой требует человека | Интеграционный тест HR |
| Отзыв согласия | Нет доступа и новых вызовов подготовки | Интеграционный тест HR |
| Кабинет | Прежние элементы и проигрывание; обновляются только данные | Проверка существующего компонента |
| Выпуск | Проверенная версия обоих процессов, совместимый откат и живое чтение | После разрешённого релиза |

Проверки выполняются без реальных приглашений и без подмены согласий. Сохранённые
входы подтверждают совместимость, но не полный живой цикл публикации.

## Проверено до выпуска

- 12 тестов самостоятельного сервиса; 51 тест адаптера, маршрутов кабинета,
  хранилища и core bridge; ещё 76 регрессий Верстака, рекомендаций и уведомлений.
- TypeScript: `npm exec tsc -- --noEmit`.
- Сохранённые текущие ответы production: 7 оценок × 3 профиля вакансий,
  21 совместимое представление, 4–7 параметров, уровни совпадают с ядром.
  Реальный неизвестный вес имеет значение `insufficient_data`; он исключается,
  а не заменяется нулевой важностью в исходных данных.
- Два текущих реальных интервью через отдельный локальный HTTP-процесс и живой
  CPA: обе подготовки завершены; 0 и 9 фрагментов в выбранных представлениях.
  Повторное чтение и другая вакансия не добавили вызовов модели.
- Браузер: существующая Орбита с реальным представлением; точная передача
  записи и времени `1220.31` плееру, обновление версии без перезагрузки.
  Обновление версии в этом браузерном сценарии — явно синтетическое событие.

Приватные входы и результаты: `output/employer-core-connection/`;
скриншот: `output/playwright/employer-core-display.png`. В релиз они не включаются.

Ограничение живой приёмки: на момент проверки ядро сообщает
`complete_hr_materials_required` для уже согласованных участий. Поэтому проверка
публикации новой текущей оценки именно через эти участия ожидает данные ядра.
Обвязка не исправляет и не запускает ядро, не создаёт согласия; карточки должны
оставаться доступными, а подготовка — ждать автоматически.
