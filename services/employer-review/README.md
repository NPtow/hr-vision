# Подготовка оценки для кабинета работодателя

Один отдельный HTTP-процесс и SQLite. Получает сохранённую оценку ядра и точные
реплики интервью. Не оценивает кандидата, не вызывает оценщик, не меняет интерфейс.
Один набор цитат переиспользуется для вакансий; подборка и Орбита получают одну
проекцию с исходным `run_id`. До трёх фрагментов на параметр, текст и таймкоды
копируются из материалов. Модель возвращает только идентификаторы реплик.

Путь: рекомендация → одобрение команды → согласие кандидата → подготовка →
показ работодателю. Отсутствие подходящей цитаты допустимо; ошибка провайдера —
задача команде и только ручной повтор. Открытие карточки не запускает модель.

## Граница

HR API владеет авторизацией, согласиями, материалами и публикацией. Он передаёт
готовый результат ядра и снимок разрешённых материалов. Этот процесс владеет
подбором цитат, сохранёнными заданиями и представлением оценки. Не читает HR БД.
Пока методология отбора отложена: адаптер принимает порядок параметров для конкретного
участия в вакансии; по умолчанию сохраняется порядок ядра. Максимум 7, вероятность
недостатка данных > 0.5 исключает параметр. Автоматический выбор важности не придуман.
Если пригодных меньше пяти, сервис не добавляет выдуманные оценки.

HTTP слушает localhost, все `/v1/*` требуют сервисный Bearer token. Секреты
передаются через окружение, не браузер. `POST /v1/preparations` принимает
`candidateId`, `assessment`, `sourceRevision`, `chunks`. Оценка соответствует
`full-corpus-level-choice-v1`. `GET /v1/preparations/{id}` читает статус.
`POST /v1/presentations` принимает `preparationId`, `preferredParameterIds` и
возвращает существующий DTO Орбиты. Уровни не пересчитываются: для нынешней
пятиуровневой шкалы отображается номер выбранного уровня. Другие шкалы требуют
явного контракта отображения и отклоняются. Недостаток данных не превращается в 0.

`GET /v1/tasks` — сохранённые ошибки, требующие человека.
`POST /v1/preparations/{id}/retry` с `requestId` — ручной повтор.
Повтор исходного POST всегда читает прежнее задание, включая ошибку. После падения
процесса начатый внешний вызов становится задачей, автоматически не повторяется.

## Запуск

`python3 services/employer-review/service.py` (Python 3.9+, stdlib).
Переменные: `REVIEW_TOKEN` (64 hex), `REVIEW_DB` (собственный файл SQLite),
`REVIEW_PORT` (8098), `REVIEW_LLM_BASE_URL`, `REVIEW_LLM_KEY`, `REVIEW_LLM_MODEL`.
Провайдер — существующий OpenAI-совместимый CPA; модель выбирается конфигурацией.
`GET /healthz` подтверждает процесс, не качество модели или подключение кабинета.

Кабинет: `HR_EMPLOYER_REVIEW_ENABLED=1`, `HR_EMPLOYER_REVIEW_URL`,
`HR_EMPLOYER_REVIEW_TOKEN`. Новое участие из `employer_store.import_batch` ставится
в подготовку; ранее опубликованные участия автоматически не переносятся.
Подборка и `employer/interview-assessment` читают `employer_review.projection`.
Имеющаяся анимация не переписана. Удалён только фильтр, скрывавший балл без цитаты.

Для команды (существующая авторизация HR):

- GET `/api/hr/selection/review-tasks` — ошибки и устаревшие версии.
- POST `/api/hr/selection/review-prepare` — `{applicationId, preferredParameterIds}`;
  только уже согласованное участие, без приглашений или подмены согласия.
- POST `/api/hr/selection/review-retry` — `{applicationId, requestId}`;
  после исправления причины ошибки. Другой результат ядра создаёт новую подготовку.

Установка: разместить проверенную версию в
`/opt/hr-vision-employer-review/releases/<commit>/`, выполнить её `deploy/install.py`
от root. Он использует существующий CPA, создаёт собственный systemd-процесс и
конфигурацию адаптера, но **не перезапускает HR API**. Обновить проверенный
`interface-lab/deploy/ci/receiver.py`, затем выпустить API штатным guarded deploy.
Обновление процесса допускается после завершения очереди; приватную SQLite
сохранять вместе с обычными резервными копиями состояния сервера.

Откат: отключить флаг для новых участий и worker, сохранив подготовленные данные и
проверку доступа в совместимом API. Старый API без проверки публикации запрещён
приёмником, если `er_preparations` уже содержит записи. Не удалять строки для обхода
этой защиты. Остановленный во время запроса процесс переводит начатую операцию
в ручную задачу; повтор сам не выполняется. Диагностика: `/v1/tasks`,
`systemctl status hr-vision-employer-review`, `journalctl -u hr-vision-employer-review`.

## Приёмка этой версии

| Сценарий | Ожидаемый результат | Проверка |
|---|---|---|
| Одна оценка в двух потребителях | Один run_id и те же значения | Интеграционная + реальные данные |
| Две вакансии | Одна подготовка цитат, разные разрешённые представления | Тест с подсчётом вызовов |
| Повторное открытие | Нет вызова модели | Тест + повтор API |
| Источник и таймкоды | Дословные существующие реплики, одна запись на фрагмент | Проверка каждого реального результата |
| Нет цитаты | Оценка сохранена, evidence пустой | Тест представления |
| Сбой / перезапуск | Задание команде, нет автоматического повтора | Изолированный тест |
| Согласие и публикация | Неподготовленный кандидат скрыт | Интеграционный тест HR |
| Чужой доступ / новая версия | Отказ, старые результаты не выдаются как текущие | Интеграционный тест HR |
| Рабочий кабинет | Нынешние стрелки, поворот и переход к видео | Браузер, без изменения UI |

Версия `employer-quotes-2026-10-26.4`: локальный HTTP-процесс проверен на трёх
реальных сохранённых оценках ядра (по 16 параметров) и соответствующих расшифровках,
с живым `gemini-3.8-flash-high` через CPA. Все три подготовки завершились, у каждой
7 отображаемых параметров. Исходные баллы/версия сохранены; повтор запроса и другая
вакансия не вызвали модель. Это проверка сохранённых входов, а не новое согласие
кандидата или приёмка полного рабочего кабинета в production.

Проверены: 9 тестов сервиса, 6 тестов адаптера на настоящей временной SQLite,
85 тестов приёмника, регрессии работодателя/подборки и TypeScript. В браузере
проверен существующий компонент Орбиты с полученным DTO: 7 навыков, балл без
цитаты, стрелки источников и передача точной записи/таймкода `04:29` плееру.
Приватные входы, ответы и логи находятся в локальном `output/employer-review-acceptance/`;
они не включаются в публичный репозиторий.

Production-статус до отдельной выкладки и smoke: NOT READY. Полный цикл реального
согласия/уведомления не запускался; сервис не отправляет приглашения.
