# Подключение к рабочему Верстаку

26 октября 2026. Новый независимый процесс `hr-vision-assessment-core` слушает
localhost:8097. Существующий HR API собирает полный CV и все выбранные расшифровки
через прежний Core API, затем отправляет `{corpus, rubric}`. Секреты остаются на сервере.

Оператор в карточке кандидата нажимает «Оценить CV и интервью». Точка запуска:
`POST /api/hr/selection/candidates/{id}/assessment`, тело `{revision}` из текущей
карточки. Обычная manager-сессия и проверка версии обязательны. Чтение:
`GET /api/hr/selection/candidates/{id}/readiness`. GET не запускает оценку.

Каждый параметр получает тот же полный корпус. Неизменные материалы и шкалы
возвращают сохранённый запуск. При изменении CV/расшифровки старый результат
помечается устаревшим. Неопределённый исход вызова не отправляется в JEV повторно.

Для первого рабочего теста используется каталог существующей аналитики:
16 параметров, пять общих описаний уровней, плюс «недостаточно данных».
Версия `2026-10-25.3-full-corpus-test.1` видна в карточке. Пользовательские 15 шкал,
веса вакансии и ранжирование кандидатов этой поставкой не вводятся.

## Последовательность поставки

1. Экспортировать `services/assessment-core` из проверенного Git commit в
   `/opt/hr-vision-assessment-core/releases/<40-char SHA>`.
2. На outreach от root выполнить `python3 <release>/deploy/install.py <release>`.
   Скрипт переиспользует ключ и локальный egress существующей аналитики, создаёт
   отдельный service token и systemd drop-in для HR API. Он запускает только новый
   процесс; HR API не перезапускает. Обновление уже работающего core на другой SHA
   запрещено этим установщиком и требует отдельной проверки фоновых задач.
3. Обновить проверенный receiver: новый API-архив содержит `assessment_corpus.py`
   и `assessment_core_bridge.py`. После появления `ac_bindings` receiver запрещает
   откат на API без этих модулей.
4. Выпустить UI/API штатным GitHub Actions → guarded receiver. Только он
   перезапускает HR API, проверив текущие звонки. Переменные подключения применятся
   при этом рестарте. Нельзя обходить guard или менять production current вручную.
5. Проверить текущий commit, HTTP health, три реальных запуска через manager API,
   число источников и параметров в сохранённых планах, затем интерфейс.

Файлы состояния: `/var/lib/hr-vision-assessment-core/runs.sqlite3` (полный приватный
вход и ответ), `ac_bindings` в существующей HR DB (ревизии и связь с кандидатом).
Core использует отдельного systemd DynamicUser. В браузер не отдаются исходные
приватные записи журнала или ключ JEV. ASR и отправка сообщений не вызываются.
