# Работодатель: постоянная карточка кандидата

Статус: 14 октября 2026, пользователь утвердил вариант C и поручил перенести его в кабинет работодателя. Реализованы карточка, сохранение этапов и интеграция с реальным API; выпуск отслеживается в Veritas `task_20261013_WPnILA`. Figma остаётся источником внешнего вида, а материалы берутся из сохранённых данных кандидата.

## Зафиксировано пользователем

1. Раздел «Кандидаты» — кандидаты на рассмотрении для конкретной вакансии. В этот пул приходят через раздел «Кандидаты» и выбор вакансии.
2. Вакансия хранит уже выбранных кандидатов, с которыми нанимающий продолжает работу по воронке. Компактное переключение выбранных людей — аватары сверху с именами при наведении и доступным названием при работе с клавиатуры.
3. Один кандидат в рамках вакансии имеет постоянную карточку. Интервью, профиль, встречи и решение/оффер относятся к этой карточке; переход по календарю не должен создавать другую карточку или выбирать другого человека.
4. Только успешное назначение встречи переводит человека из пула рассмотрения в выбранных по вакансии. После назначения открывается эта же карточка в контексте вакансии. Если назначение отменили или оно не сохранилось, кандидат остаётся на рассмотрении.
5. Пропущенный кандидат возвращается после остальных. После отказа нанимающий больше не видит его в своём рабочем потоке. Исчерпание подборки показывает согласованное пустое состояние и запрос следующих кандидатов.
6. Календарь общий по вакансиям текущего работодателя. Встреча явно подписана своей вакансией. Прошедшие встречи исчезают из будущей повестки, но сохраняются в истории карточки. В вакансии появляется переход «Ждут вашего решения · N» к соответствующим кандидатам.
7. Текущие независимые UI-правки: вертикальная повестка МашаДаша_UI, сайдбар из иконок с названиями по наведению/фокусу, полное удаление строки «Все кандидаты» со счётчиком.
8. Заголовок в разделе «Кандидаты» переключает вакансии. Белая полоса сайдбара и подложка группы иконок убраны; у оболочки единый фон. Опубликовано агентом в `f2552b203010a15e029921fdbf9cf1ea43b9507b`, CI `38471426858` успешен, публичный SHA совпал; API не перезапускался.
9. Постоянная карточка отражает этап воронки. Действия раскрываются по контексту; постоянный ряд из «Ещё встреча», «Оффер», «Отказать» не подходит. На экране остаётся один основной следующий шаг, остальные появляются по запросу.

## Путь

Кандидаты → выбор вакансии → рассмотрение → назначение встречи → выбранный кандидат в вакансии → встреча → решение → оффер.

У вакансии без выбранных людей — пустое состояние выбранного списка; оно не должно автоматически подменяться пулом рассмотрения. Доступ к пулу остаётся через раздел «Кандидаты».

Уточнения пользователя:

- Нажатие на стадию открывает только её материалы. Просмотр прошлого не откатывает состояние кандидата и не удаляет последующие стадии.
- Интервью рекрутера находится только на первой стадии. У каждой встречи и каждого тестового собственные результаты, документы и заметки.
- На оффере показывается только предложение для кандидата.
- Через «+» раскрывается выбор следующего шага: встреча, тестовое или оффер. Встречи и тестовые могут повторяться; каждый повтор — новая стадия с отдельной историей.
- Воронка растёт из фактически добавленных этапов, без фиксированного счётчика «4 из 4».

## Расхождения, исправленные при переносе в кабинет

- Вакансия всегда открывает выбранных кандидатов. При пустом списке подборка `proposed` автоматически не подставляется.
- Глобальный `FeedbackGate` и принудительный переход к чужой вакансии убраны из реального кабинета. Сохранённые оценки видны внутри своей встречи; следующая стадия не требует вымышленной анкеты.
- Выбранные кандидаты используют отдельную постоянную карточку; подготовленные intake-профили остаются в подборке и не смешиваются с выбранными.
- Общий календарь уже получает встречи всех вакансий текущего workspace. Для его текущей перерисовки новая агрегация на сервере не требуется.

## Проверка следующей реализации

- Отмена и ошибка назначения не перемещают кандидата; успешное назначение открывает именно его карточку в нужной вакансии.
- Пул рассмотрения и выбранные люди не смешиваются, включая подготовленные intake-профили.
- Переход из календаря сохраняет vacancy/application/candidate/meeting identity и права текущего работодателя.
- История проведённых встреч и офферов остаётся доступной в карточке; список будущих встреч не показывает прошедшие и отменённые события.
- Созданные для проверки сценарии остаются локальными; тестовые встречи, согласия и уведомления в реальную базу не добавляются.

## Реализация карточки C

- `CandidateStageCard` показывает только выбранную стадию: первичное интервью, конкретную встречу, тестовое или версию оффера. Меню «+» открывает форму следующего шага внутри той же карточки.
- `CandidateStageWorkspace` связывает формы с API. Просмотр истории не изменяет воронку; `applicationId`, `vacancyId` и `stageId` сохраняются в URL. Back/Forward восстанавливает нужную вакансию; во время активного звонка смена контекста ждёт завершения разговора.
- `cp_meetings` и `cp_offer_versions` остаются источниками встреч и офферов. `cp_test_assignments` хранит тестовые; `cp_employer_stages` хранит только порядок, частные заметки и ссылки материалов. Новая встреча, повторное тестовое и новая версия оффера не перезаписывают предыдущие этапы.
- Редактирование использует ревизию на момент открытия формы, повтор запроса после потери ответа сохраняет тот же requestId. Неизменённый оффер возвращает к существующему этапу.
- Первичное интервью загружается своим API, запись исторической встречи — только по её meetingId. В макете было демонстрационное видео; в приложении оно не подставляется вместо реальной записи.
- Тестовое сохраняется как этап с условиями, результатом и ссылками на материалы. Автоматическая отправка задания кандидату в этот выпуск не входит и в интерфейсе не обещается.
- Основные условия оффера ограничены 240 символами, ожидания — 12 000; предыдущие версии и их документы доступны только для просмотра.
- У старых заявок без первичного интервью профиль и CV доступны через меню карточки, без добавления фиктивного интервью.
