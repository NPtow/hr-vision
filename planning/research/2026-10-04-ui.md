# HR Vision: готовые компоненты панели работодателя

Проверено 4 октября 2026 года. Исследование и предложения для согласования, не спецификация утверждённого интерфейса и не отчёт о реализации. Исходники приложения, зависимости и внешние системы в рамках этого исследования не изменялись.

## Текущая рамка

- Работаем только со стороной работодателя. Интерфейс кандидата и интеграция доставки сейчас вне задачи.
- Вход начинается с задач найма, затем открывается конкретная задача и её подборка. Встречи становятся доступны по мере их назначения.
- После состоявшейся встречи нужен обязательный отзыв, затем оценка кандидата с основаниями для решения.
- Пул кандидатов для оффера не ограничен числом 3 или другим фиксированным максимумом.
- Офферы идут последовательно: одному кандидату, затем ожидание результата. Принятие останавливает последовательность; отказ позволяет перейти к следующему.
- Состав переходов, порядок кандидатов в пуле, точный момент конфетти и механизм фиксации ответа требуют согласования. Эта записка их не утверждает.

## Ранняя рекомендация

Максимально использовать уже существующие shadcn-компоненты и добавить официальные Radix-варианты `Collapsible`, `Checkbox`, `RadioGroup`, `Field`; `Sheet` нужен только если выбранный вариант панели предполагает боковые детали. Для оффера достаточно структурированных условий, `Textarea` для личного сообщения и читаемого предпросмотра. Полноценный редактор документов на первом этапе не нужен.

Это рекомендация по строительным блокам. Выбор компоновки подборки делается отдельно после сравнения альтернатив.

## Проверенная локальная база

В `interface-lab/package-lock.json` зафиксированы React `19.3.0`, `radix-ui` `1.6.7`, Motion `13.4.6`. Компоненты `Button`, `Dialog`, `Tabs`, `Input`, `Textarea` уже адаптированы из официального shadcn `new-york-v4`, лицензия MIT сохранена. В `Dialog` используются примитивы из `radix-ui`; тема портала и русская подпись закрытия уже настроены. Формы RHF/Zod и confetti пока не установлены.

Существующий README обозначает интерфейс как прототип с локальным состоянием и вымышленными данными. Наличие этих компонентов не подтверждает production-права, сохранение, календарь или отправку.

## Что брать из shadcn/Radix

| Задача | Готовый блок | Предлагаемое минимальное применение |
|---|---|---|
| Выбрать задачу найма | `Button`, при необходимости `Item` | Название задачи, краткий текущий статус, следующее требуемое действие; детали выбранной задачи открываются в её контексте |
| Посмотреть кандидата | Обычная область страницы либо `Sheet` | Имя, соответствие задаче, основания, неизвестное, ближайшее действие; конкретный вариант зависит от выбранной компоновки |
| Раскрыть доказательства | `Collapsible` | Основной вывод виден сразу; цитаты, источник и дата раскрываются рядом с ним |
| Назначить встречу | `Dialog`, `RadioGroup`, `Button` | Выбор доступного времени или запрос другого времени; конкретная календарная реализация здесь не выбирается |
| Написать отзыв | `Field`, `RadioGroup`, `Textarea` | Понятная оценка по критерию и наблюдение, на котором она основана; пустой ответ отличается от «не удалось оценить» |
| Собрать пул офферов | `Checkbox` | Независимый выбор нескольких кандидатов без верхнего лимита; способ задания очереди пока открыт |
| Свернуть остальных | `Collapsible` | Предложение: «Остальные кандидаты (N)», с сохранением данных и возможностью вернуть кандидата; сворачивание не означает отказ |
| Подготовить оффер | `Field`, `Input`, `Textarea`, `Button` | Согласованные условия, личный текст, предпросмотр конкретного оффера |
| Показать ошибку | `FieldError` и текст у действия | Причина и способ исправления остаются видны; исчезающий toast не является единственным сообщением |

Источники: [shadcn Collapsible](https://ui.shadcn.com/docs/components/radix/collapsible), [Sheet](https://ui.shadcn.com/docs/components/radix/sheet), [Field](https://ui.shadcn.com/docs/components/radix/field), [Checkbox](https://ui.shadcn.com/docs/components/radix/checkbox), [Radix RadioGroup](https://www.radix-ui.com/primitives/docs/components/radio-group).

### Важная совместимость документации

Текущий shadcn разделяет Base UI, Radix UI и React Aria. Общий адрес `/docs/components/collapsible` при проверке перенаправлял на Base UI. Context7 также возвращает примеры всех трёх вариантов в одном ответе. Для этого проекта выбирать `/docs/components/radix/...` и проверять импорты. У Radix применяется `asChild`; нельзя механически смешивать его API с `render`, `isExpanded` или массивами значений из других вариантов.

`Collapsible` управляется через `open`/`onOpenChange`, поддерживает Enter/Space и даёт `--radix-collapsible-content-height` для изменения высоты. Это готовая основа обратимого раскрытия, а не причина писать собственный disclosure. [Radix API](https://www.radix-ui.com/primitives/docs/components/collapsible).

Для форм подходит официальный паттерн shadcn: React Hook Form `Controller`, `Field`, `FieldLabel`, `FieldError`, `aria-invalid`; схема Zod проверяет данные до обработки submit. Описания и ошибки нужно явно связать с контролом через ARIA. Состояние ошибки принадлежит полю, а не только цвету рамки. [Официальный пример форм](https://ui.shadcn.com/docs/forms/react-hook-form).

## Принципы поведения и доступности

Ниже проектные предложения, не утверждённые переходы:

1. На каждом шаге держать одно основное следующее действие и доступный путь назад. Не показывать заранее пустые разделы будущих этапов.
2. Обязательность отзыва проверять при переходе дальше по процессу. Не превращать её в незакрываемое окно: пользователь должен иметь возможность выйти, вернуться к задаче и закончить отзыв позднее. Точная область блокировки требует решения.
3. Не принимать наступление времени окончания встречи за доказательство её проведения. Не смешивать «не оценено» с отрицательной оценкой. Оценку связывать с наблюдением, источником и конкретным требованием роли; единый автоматически рассчитанный балл здесь не предлагается.
4. Открытие/закрытие деталей должно сохранять контекст и возвращать клавиатурный фокус к исходному кандидату. После смены этапа фокус переводится на заголовок нового содержимого; сворачивать область с оставшимся внутри фокусом нельзя.
5. В `Sheet`/`Dialog` сохранять заголовок, Escape и управление фокусом Radix. Настраивать `onOpenAutoFocus`/`onCloseAutoFocus` только при реальной необходимости. [Dialog API](https://www.radix-ui.com/primitives/docs/components/dialog).
6. Проверять клавиатуру, длинные русские подписи, увеличение текста, ширины 390/768/1024/1440 px и reduced motion. Не делать основное действие зависимым только от hover.

Для простого раскрытия достаточно готового поведения Radix и короткого изменения прозрачности/высоты. Если выбранная компоновка потребует перестройки карточек, использовать уже установленный Motion. `MotionConfig reducedMotion="user"` учитывает системное предпочтение; `useReducedMotion` позволяет отдельно управлять декоративными эффектами. Это не отключает произвольный canvas автоматически. [Motion accessibility](https://motion.dev/docs/react-accessibility).

## Геометрия и визуальные правила

Apple документирует согласование вложенных радиусов и отступов, оптическое выравнивание и выражение иерархии компоновкой. Для плотных настольных контролов скруглённые прямоугольники остаются допустимой формой; капсула не обязательна для каждой кнопки. [WWDC25: Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/).

Наш перенос на веб: сохранить текущую типографику Inter и тему проекта; настроить единые роли отступов «внутри контрола / между связанными элементами / между группами». Вложенные скругления проверять вместе с полями. `r_inner ≈ max(0, r_outer − inset)` служит ориентиром для равномерно вложенных круговых углов, а не универсальной формулой Apple. Конкретные радиусы, модуль 4/8, длительность и ширина панели являются решениями HR Vision. Не добавлять стекло и blur туда, где они не помогают чтению. Фокус, ошибки и недоступные состояния должны различаться без одной лишь смены цвета.

## Оффер: простая форма и последовательность

**Предлагаемый интерфейс:** один выбранный кандидат, согласованные условия с возможностью проверить источник, личное сообщение, предпросмотр. Неизвестные или несогласованные значения остаются пустыми и явно обозначенными. Поля могут включать роль, вознаграждение с периодом и валютой, формат работы и дату начала, но точный обязательный состав ещё нужно согласовать.

Пул может быть любым по размеру. На экране подготовки всегда виден конкретный адресат; состояние ожидания относится только к текущему офферу. Принятие останавливает очередь, отказ открывает возможность подготовить следующий. Метод выбора следующего кандидата, действия при отсутствии ответа и механизм записи принятия/отказа здесь не устанавливаются. Кнопка отправки и интеграция доставки пока не реализуются и не выбираются.

Полезный внешний паттерн: Greenhouse сначала создаёт запись оффера с условиями, затем позволяет перейти к следующему действию с оффером. Для HR Vision заимствуем разделение редактируемых условий и последующего действия, не весь ATS-процесс. [Create an offer](https://support.greenhouse.io/hc/en-us/articles/200721744-Create-an-offer).

| Вариант | Вывод для текущего этапа |
|---|---|
| shadcn + RHF/Zod + обычный предпросмотр | Рекомендуемая основа: условия структурированы, текст прост, все контролы знакомы |
| Tiptap | Отложить до подтверждённой потребности в форматировании, списках или редакторе шаблонов. Open-source ядро MIT; платные расширения и облачные функции имеют отдельные условия. [Документация](https://tiptap.dev/docs/editor/getting-started/overview) |
| React Email | Возможная будущая генерация HTML/plain text из утверждённого шаблона; это не решение о доставке и не текущая зависимость. [Render API](https://react.email/docs/utilities/render) |

## Конфетти: готовое средство, триггер ещё не выбран

Рекомендация библиотеки: `canvas-confetti` напрямую, без React-обёртки. Она предоставляет `confetti.create(canvas, options)`, отдельный экземпляр для локальной области и `reset()` для остановки и очистки. [API](https://github.com/catdad/canvas-confetti/blob/master/README.md#api).

**Предложение для согласования:** один небольшой burst после успешного явного перехода к подготовке оффера. Альтернативные моменты, например принятие оффера, пока не выбраны. Запуск на каждом checkbox, открытии страницы или восстановлении состояния не рекомендуется. «Как Telegram Premium» трактуется как краткое чувство завершения; точный эффект Telegram не исследован и не обещается.

Технический контракт после выбора триггера:

- `disableForReducedMotion: true`; дополнительно проверить `matchMedia('(prefers-reduced-motion: reduce)').matches` непосредственно перед запуском. Исходник библиотеки считывает это предпочтение при создании экземпляра, поэтому одного первоначального значения недостаточно для изменения настройки во время работы.
- Свой canvas с `aria-hidden="true"` и `pointer-events: none`; основной результат действия подтверждается постоянным текстом.
- Один burst, ориентировочно 35–50 частиц и до 1,2 секунды. Это предложенная интенсивность, не норматив и не утверждённый дизайн.
- `ticks` обозначает обновления, а не миллисекунды. Жёсткое ограничение времени реализуется таймером `reset()`; cleanup очищает таймер и экземпляр. Для такого объёма достаточно `useWorker: false`.

Источник нюансов: [canvas-confetti source](https://github.com/catdad/canvas-confetti/blob/master/src/confetti.js#L513-L580). `react-canvas-confetti` имеет смысл при выборе готовых пресетов; для одного события добавляет лишний слой. [Обёртка](https://github.com/ulitcos/react-canvas-confetti/blob/master/README.md).
