# Связанный тест HR Vision

Публичная статика и API размещены на outreach. API: `hr-vision-api`, loopback 8391, проксируется только отдельным `hr-vision-web` (8381); TLS вход остаётся на dsa. Сборка UI локальная, просмотр/проверка только по публичному HTTPS. Локальный web-сервер не нужен.

## Состояние и доступ

SQLite `/var/lib/hr-vision-api/journey.sqlite3`, режим WAL, все команды под `BEGIN IMMEDIATE`. Перезапуск приложения/выкладка не сбрасывает прогресс. Права процесса `hr-vision`, MemoryMax 256M. Выпуски `/opt/hr-vision-api/releases/`, указатель `current`.

Общий вход: story `hr-vision-product--start`. При первом открытии приватной ссылки `#team=…` сервер запоминает доступ на 30 дней в подписанной Secure/HttpOnly/SameSite cookie; после проверки ключ убирается из адресной строки. Повторный вход по обычному адресу и в новой вкладке показывает четыре готовых аккаунта без поля для кода. Старые открытые сессии мигрируют автоматически. Без приглашения или сохранённого доступа новый браузер видит понятное сообщение, персональные данные закрыты. Авторизованная кнопка «Скопировать общий вход» получает полную ссылку через API.

Сам HTML/JS ключа не содержит. Ключ хранится в `/etc/hr-vision/api.env` (root, 600), параметр `HR_TEAM_KEY`; его ротация отзывает cookie доступа. Это доступ команды ко всем четырём тестовым аккаунтам, не production-авторизация реальных кандидатов. API сессии выбирают роль на сервере, токены сохраняются отдельно в каждой вкладке. Cookie разрешает только выбор аккаунта; чтение и изменение состояния по-прежнему требуют сессию выбранной роли. Фидбек работодателя скрыт от кандидатов; черновик оффера также скрыт.

Кандидат принимается вручную или режимом auto, но встреча всегда требует ручного подтверждения. Слот 30 минут; pending/confirmed/live занимают время кандидата и работодателя. Повторный выбор старого времени возвращает 409. Команды содержат generation, чтобы вкладка до сброса не перезаписала новый тест. Встречи/чаты раздельные по кандидатам. Один отправленный оффер; принятие закрывает подбор. Изменённые условия увеличивают версию: ответ на старую версию отклоняется.

## Выкладка

`bash interface-lab/scripts/deploy-api-yc.sh` обновляет только отдельный HR Vision API и Caddy origin. Выполняет unit tests на outreach, сверяет активный Caddy с файлом, сохраняет backup и проверяет HTTP. При первом создании ключ генерируется автоматически. Ключ и SQLite не входят в выпуск.

`npm --prefix interface-lab run deploy:yc` публикует статический UI. Серверный Python и `.env` не попадают в статику. Старый UI-код сохранён в `AgencyProductPreview.tsx`, `ManagerWorkspace.tsx`, `CandidateWorkspace.tsx`.

## Фидбек по фактическому интервью

`meeting.transcript` сохраняет финальные реплики работодателя в его активной встрече. При `meeting.finish` фиксируется анкета из реально заданных вопросов. `POST /api/hr/feedback/questions` доступен только работодателю после завершения: использует уже замороженную анкету или получает готовый Daily VTT вне блокировки общей базы. Нет транскрипта/нет распознанных вопросов: status processing/missing/unavailable, без выдуманных вопросов. `feedback.questions` позволяет явно указать свои заданные вопросы. `feedback.draft` и `feedback` требуют текущие meetingId/questionnaireId; отправка требует ответ на каждый вопрос. Анкета, черновик и фидбек скрыты от кандидата. Старые сохранённые отзывы поддерживаются только для чтения.

Извлечение детерминированное, без LLM. Это не автоматическая оценка кандидата. Вся синхронизация остаётся в текущем серверном тесте; реальные Telegram-уведомления и продуктивная аутентификация не добавлены. Новые проверки: `test_feedback`, `test_feedback_http` (временная отдельная SQLite и HTTP на outreach), всего 34 с domain/provider suite.

## Подключение исходной панели ДСА

`GET /api/hr/dsa-candidates` доступен только с сессией работодателя. Сервер читает `https://kabinet.158-160-179-53.sslip.io/api/candidates`, кеширует результат на минуту в памяти и переводит явно разрешённые поля в DTO. Данные кандидатов не входят в JS-сборку и Git. Ошибка источника показывается явно. Сетевой запрос выполняется вне блокировки общей SQLite.

У работодателя есть отдельная задача «ДСА Инжиниринг». Видео воспроизводится через уже существующий `/api/video/{id}` исходного кабинета; сервер источника обновляет ссылку Яндекс Диска. Короткая версия использует исходные границы фрагментов; полная версия показывает исходные главы. Описания глав и прямые цитаты различаются. Профиль, резюме, оценка рекрутера и исходный статус сохраняют происхождение. Адаптер не записывает решений в исходную панель и не превращает старые материалы в подтверждение новой вакансии или встречи. Тестовые кабинеты реальных кандидатов не создаются; текущий тест «Сфера» остаётся отдельно.
