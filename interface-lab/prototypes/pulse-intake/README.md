# Пульс Логистика · анкета для подбора лидогенератора

Работающая анкета с непрерывной лентой вопросов и ответов. Слева — темы и короткие записи ответов.
По умолчанию вопросы идут по порядку; нажатием на тему можно выбрать, на что отвечать.
Текущий вопрос крупно показан в конце ленты; предыдущие ответы остаются видимыми.
При смене темы меняется только вопрос, на который ещё не ответили. Новый ответ виден
сразу; если человек читает предыдущие сообщения, следующий вопрос не сбрасывает прокрутку.
Кнопка со стрелкой возвращает к текущему вопросу. Текст — от 16 CSS px, вопрос — 24–30 px.
На телефоне темы открываются вкладкой «Заявка». Голосовой ответ сначала попадает в
редактируемое поле и отправляется только кнопкой отправки.

## Содержание

18 тем, 12 ключевых: результат работы, услуга, клиент и собеседник, квалификация,
текущий процесс, ожидания, граница ответственности, каналы, передача в продажи,
ресурсы, бюджет инструментов, опыт, самостоятельность, обучение, формат, оплата,
проверка кандидата и дата выхода. Вопросы помогают сформировать профиль найма,
а не требуют от заказчика заранее знать название должности.

Один ответ может заполнить несколько тем. Краткая запись хранится вместе с точными
цитатами. «Не знаю» остаётся неизвестным. Ручные правки защищены от изменений моделью.
Версии промптов сохранены в `prompts/`; текущая версия — `prompts/v3/`.
Модель получает выбранную тему и показанный вопрос, поэтому короткий ответ имеет контекст.

## Реализация и источники

Python + SQLite + HTML/CSS/JS, без сборки фронтенда. Три стадии: извлечение со строгой
схемой и проверкой дословных цитат, короткий вопрос до 220 символов, отдельная проверка
вопроса и кратких записей на выдумку. При отклонении показываются исходные цитаты и
заранее написанный вопрос. У стадий есть версии, хеши, кэш, ограниченный бюджет и одна
попытка исправления невалидного ответа. Результат хода также идемпотентен.

Через Context7 найден [CopilotKit Form Filling Copilot](https://www.copilotkit.ai/examples/form-filling-copilot).
Проверены [исходники на 99f29ee5](https://github.com/CopilotKit/CopilotKit/tree/99f29ee545a2ca96c84d4a151f079197eefff525/examples/v1/form-filling)
и [useFrontendTool](https://docs.copilotkit.ai/reference/hooks/useFrontendTool).
Здесь используется идея диалога рядом с общей формой; runtime CopilotKit не установлен,
его код в приложение не копировался.

Дизайн — веб-адаптация принципов [Apple typography](https://developer.apple.com/design/human-interface-guidelines/typography)
и [layout](https://developer.apple.com/design/human-interface-guidelines/layout): системный шрифт,
чёткая иерархия, связанные отступы и радиусы, немедленная реакция на нажатие,
светлая/тёмная палитра, reduced motion, reduced transparency и повышенный контраст.
Это выбранные размеры для веба, а не спецификация внутренних компонентов Apple.

Голос: [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)
и [Deepgram pre-recorded speech-to-text](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded),
`nova-3`, русский язык. Максимум 2 минуты / 5 MB за запись, 60 обращений на анкету.
Ключ остаётся на сервере. Аудио обрабатывается в памяти и не сохраняется приложением;
результат распознавания кэшируется. Микрофон включается только после нажатия. Есть отмена,
остановка при уходе со страницы, обработка отказа в разрешении и ограничение времени.

## Размещение в YC

Публичный адрес: `https://pulse.158-160-179-53.sslip.io/`.
Анкета открывается по отдельной ссылке с фрагментом приглашения, который обменивается
на HttpOnly / Secure / SameSite cookie. Приглашение относится к одной общей анкете:
по той же ссылке заказчик и рекрутер видят сохранённые ответы. API без приглашения закрыт.
Саму ссылку не хранить в Git, публичной документации или логах.

Приложение и отдельный Caddy-контейнер живут на outreach:

- исходники: `/srv/pulse-intake/releases/<release>`, текущая версия — симлинк `current`;
- настройки и ключи: `/etc/pulse-intake/app.env`, root:root 600;
- ответы: `/var/lib/pulse-intake/state.sqlite3`, отдельный UID 10001, каталог 700;
- Python: `127.0.0.1:8392`, прокси: `10.130.0.18:8393`, принимает только dsa;
- dsa завершает TLS; отдельный import `/etc/caddy/pulse-intake.caddy`;
- лимиты: 256 MB / 0.5 CPU для приложения, 64 MB / 0.25 CPU для прокси;
- read-only контейнеры, постоянные данные вне релиза, ограниченные журналы.

Состояние на сервере является основным. Изменения проверяют номер ревизии: устаревшее
окно не перезапишет свежий ответ. Повтор одного хода возвращает уже сохранённый результат.
В браузере отдельно сохраняются неотправленные ответы по темам. Старый локальный черновик
версии 1 копируется в резервный ключ перед обновлением, исходные ответы не удаляются.

Релиз: `python3 deploy/release.py`. Он не меняет соседние службы и общий Caddy.
Первая установка публичного маршрута: `deploy/install_public_route.py` на dsa,
с проверкой конфигурации, резервной копией и защитой от параллельного изменения файла.
Для отката: запустить Compose из прежнего каталога с его `PULSE_RELEASE`; базу не заменять.

## Локальный запуск и проверки

```sh
zsh run.sh
python3 -m unittest -q test_server.py
node --test test_voice.cjs
node --check web/app.js
```

Локально: `http://127.0.0.1:4318/`. `run.sh` читает ключ локального CPA без записи в код.
Для голоса задать серверную переменную `DEEPGRAM_API_KEY`.
Публичные синтетические проверки используют отдельное тестовое приглашение и отдельную
анкету, не ответы заказчика. Результаты проверок и релизный манифест лежат в `output/`
и исключены из Git. Живая проверка распознавания проводится на синтезированной речи;
микрофон пользователя автоматически не включается.

## Границы

Сервис собирает требования и выгружает Markdown. Он не публикует вакансию и не отправляет
сообщения от имени заказчика. Ссылку может использовать её получатель; это доступ к общей
анкете, а не персональный аккаунт. Ответы и кэш хранятся до административного удаления.
Узкий фильтр инъекций дополняет проверку цитат и схем, но не заменяет контроль доступа.
