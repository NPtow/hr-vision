# Ветки, worktree и выпуск

1. Начинайте задачу от актуального `origin/main` в ветке `codex/<задача>`.
2. Для параллельной задачи используйте отдельный worktree. Не смешивайте изменения
   нескольких задач в одном индексе; не сбрасывайте чужие незакоммиченные файлы.
3. Коммит содержит связное изменение. Push сохраняет код, PR запускает проверки.
   Изменения `packages/` проверяются вместе со всеми потребителями.
4. После проверки и ревью сливайте PR в `main`. Удаляйте рабочую ветку только
   после проверки, что нужные изменения сохранены.
5. Выпуск выполняйте явно из выбранного коммита. Сохраняйте SHA, manifest и
   предыдущий артефакт для отката. Версии можно отмечать тегами вида
   `assessment-core/v1.2.0`; это пример имени, не выпущенная версия.

`codex/archive/2026-10-28/*` — сохранённые варианты. Их не следует целиком
вливать в `main`: они могут содержать более старые реализации. Для возврата
функции сравните файлы со свежей версией и перенесите выбранный патч новой задачей.
Workflow этих веток сохранены как текст в `.archive/github-workflows/`.

После принятия этого PR прямой push в `main` не запускает production-выпуск.
`Deploy HR Vision` доступен через `workflow_dispatch`, только для `main` и
`codex/mockups`. Защита веток и GitHub Environments настраиваются администратором
отдельно; наличие документа само по себе их не включает.
