# Общий календарь и распределение интервью

Задача Veritas: `task_20261018_cRAKON`.

## Поведение

Один календарь используется на персональной странице приглашения
(`cp=invite-booking`) и при записи на первое интервью из кабинета кандидата
(`cp=booking`, а также вход через `cp=interview` до записи).
Кандидат выбирает дату и время; имена рекрутеров и повторяющиеся интервалы
не показываются. Используется согласованный минимальный дизайн с мягкой глубиной.
Персональная ссылка сохраняет шаг подтверждения почты и согласия.

Оба публичных входа используют `interview_scheduler.py`:

1. Собрать 30-минутные интервалы активных рекрутеров с учётом недельных правил,
   исключений на конкретные даты и уже занятых пересекающихся слотов.
2. Объединить одинаковые интервалы в непрозрачный `window_*` идентификатор.
3. При бронировании выбрать доступного рекрутера с наименьшим отношением
   занятых интервью к вместимости полной московской календарной недели.
4. При равенстве выбрать того, кому дольше не назначали интервью, затем
   использовать стабильный ID для воспроизводимого результата.
5. В одной `BEGIN IMMEDIATE` транзакции закрепить физический слот, интервью,
   атрибуцию и уведомления назначенному рекрутеру.

Вместимость недели считается из правил и исключений за все семь дней, включая
дни за границей скользящего горизонта публикации. Исторические обязательства
сохраняются. Повтор того же запроса не создаёт новую встречу и не меняет владельца.
Старый физический ID в публичном запросе трактуется как выбор интервала;
внутреннее точное назначение оператором сохраняется отдельно.

Рекрутер получает назначенную встречу в своём существующем кабинете.
Механизмы уведомлений, CV, согласия, выдачи доступа и статистики используют
сохранённую встречу и её владельца. Новых экранов рекрутера не добавлено.

## Проверки до публикации

- Полный backend: 844 теста, OK, 2 пропуска: необязательный локальный HH browser
  fixture и OCR без русских/английских Tesseract-пакетов в локальной среде.
- 11 тестов планировщика, включая конкурентную запись отдельных процессов,
  распределение по вместимости, закрытые дни, неактивные аккаунты, пересечения,
  идемпотентность и откат транзакции при ошибке outbox.
- 48 frontend tests; 39 проверок транскрипта; TypeScript typecheck.
- Service build; 33 проверки приёмника/пакета, включая замыкание Python-импортов.
- Независимое ревью: исправлены расчёт полной недели на границе горизонта и
  состояние календаря при пустом месяце/смене зоны через границу даты.

В браузере проверены оба входа с настоящим API и изолированной временной SQLite.
Два кандидата записались на одинаковое время к разным рекрутерам. Проверен
конфликт занятого слота: повторный выбор времени сохраняет введённую почту и
согласие. Проверены мобильный экран без горизонтального переполнения, пустой
месяц и переход 1 ноября 00:30 МСК → 31 октября 23:30 Калининград.
Тестовые данные синтетические, внешние отправки отключены. Эти проверки не
являются повторной проверкой живой доставки SMTP.

## Выпуск

`package-release.mjs` включает новый модуль. Root-owned приёмник должен быть
обновлён до первого выпуска; его старый полный состав сохранён в
`PRE_POOLED_RUNTIME`, разрешения и механизмы проверки не расширяются произвольно.
Публикация UI/API выполняется обычным GitHub Actions из `main`, с проверкой
активного звонка, backup базы, health и публичного `deployment.json`.
Итоговый SHA и URL workflow фиксируются в Veritas после завершения публикации.
