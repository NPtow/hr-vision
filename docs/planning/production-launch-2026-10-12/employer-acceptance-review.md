## Проверяемый путь

1. Два независимо зарегистрированных работодателя получают разные кабинеты; кандидат и внутренний командный вход не подменяют их авторизацию.
2. Вакансия принадлежит одному кабинету, переживает вход и обновление. Чужой известный ID не даёт доступ.
3. Уже прошедший первичное интервью кандидат получает реальную заявку на вакансию; согласие на вакансию и подтверждение времени — разные действия.
4. Подборка содержит только допущенных кандидатов; пропуск возвращает в конец очереди; отказанный исчезает из всех разделов работодателя.
5. Предложение встречи атомарно переводит того же кандидата в выбранных. Подтверждение, перенос, отмена и повторная встреча сохраняют правильный ID и историю.
6. Запись, расшифровка, анкета и фидбек относятся к точной встрече и не раскрываются другому работодателю или кандидату.
7. Офферы имеют версии; одновременно действует один оффер вакансии; ответ на старую версию не закрывает вакансию; принятый актуальный оффер закрывает именно её.
8. Повторные запросы и перезагрузка сохраняют идентичность и результат, не порождают дубли. Пустая выдача не создаёт вымышленных матчей.

## Доказательства

Независимый тестовый файл: `interface-lab/server/test_employer_acceptance.py`. Тесты запускают настоящий HTTP handler на localhost, отдельную временную SQLite, синтетические CV и fake Daily. Начальное интервью кандидата фиксируется как уже завершённая входная фикстура; это не доказательство реальной записи.

13 октября root повторно запустил весь набор: `python3 -m unittest discover -q` —
**384 tests, OK**. Включены 15 независимых сквозных HTTP сценариев и дополнительные
route regressions: отзыв доступа во время provider I/O, отмена предложения,
отзыв отправленного оффера, реальные cookie, частная загрузка CV.

Найденные несовпадения при сведении модулей исправлены: перенос использует
`meetingId + revision`, тип события в журнале — `type`, кандидат отвечает на оффер
через `/candidate/workflow`. Проверки авторизации и бизнес-ограничения не ослаблялись.

`npm run typecheck`, 10 проверок расшифровок, production Storybook build и
19 проверок deploy receiver прошли.

Браузерная приёмка 13 октября использует настоящий локальный HTTP handler и
SQLite, а не перехваченные JSON-ответы. Подтверждены вход только по employer cookie
без team grant, вакансия → кандидат → предложение встречи → тот же выбранный
кандидат, сохранение после reload, исчезновение из очереди, переход из карточки
вакансии, отмена встречи и отсутствие горизонтального переполнения на 390px.
JavaScript ошибок и неожиданных HTTP ошибок нет. У синтетического первичного
интервью намеренно нет записи; запрос материалов возвращает честное отсутствие
комнаты, это не проверка реального видео.

Локальные артефакты: `output/playwright/employer-backend-20261013/result.txt`,
