# Три структуры меню работодателя HR Vision

Исследование от 6 октября 2026. Приложение и серверы не менялись. Это варианты для выбора и прототипирования, не принятая архитектура.

Рекомендация: начать с **А, меню вокруг задач найма**. Оно сохраняет явные подписи и связь с вакансией. **Б, рельс с контекстной колонкой**, выигрывает при постоянном разборе очереди кандидатов. **В, верхняя навигация**, оставляет максимум ширины контенту и подходит редким посещениям кабинета. Это три разных способа организовать работу, а не три оформления одного sidebar.

## Что проверено

- По запросу пользователя применены навыки Context7 и Apple Design. Выполнены `c7 search "shadcn ui"` и `c7 search "radix primitives"`. Оба запроса завершились ошибкой разбора ответа; проверка HTTP подтвердила **429 Quota Exceeded / Monthly quota reached**. Library id не получен, поэтому следующий шаг `c7 docs` не выполнен. Получение сниппетов через Context7 не подтверждено. Исследование продолжено по официальным первичным источникам ниже.
- В локальном `interface-lab/node_modules` подтверждены React **19.3.0**, `radix-ui` **1.6.7**, Motion **13.4.6**, Lucide React **1.49.0**. Radix экспортирует `Collapsible`, `Dialog`, `NavigationMenu`, `Tooltip`, `Tabs`; peer dependencies соответствующих примитивов включают React 19. Типы нужных props прочитаны локально.
- В `src/components/ui` есть `dialog` и `tabs`, но нет готовых `sidebar`, `collapsible`, `navigation-menu` и `tooltip` wrappers. Готовый shadcn Sidebar потребует переноса и адаптации его исходников и зависимых компонентов; это не встроенный компонент `radix-ui`.
- Общий адрес shadcn `/docs/components/sidebar` сейчас перенаправляет на **Base UI**. Для этого проекта нужен явный [Radix Sidebar](https://ui.shadcn.com/docs/components/radix/sidebar): `asChild`, а не примеры Base UI с `render`.

Продуктовая предпосылка: вход через задачу найма и постепенное раскрытие следующих действий. Это соответствует прежним заметкам HR Vision, но не является новой проверкой текущей реализации. Разделы «Оценка», «Финалисты», «Оффер» предлагается держать внутри задачи и открывать по готовности, не превращать в постоянное глобальное меню.

## А. Меню вокруг задач найма

**Скелет:** слева текстовая колонка, справа одна рабочая область. Сверху название компании. Далее «Задачи найма», «Требуют решения» с числом необработанных действий и «Встречи». Ниже компактная группа «Активные задачи» с названиями вакансий; внизу профиль и настройки. Создание задачи находится рядом со списком задач. Отправка оффера остается действием конкретного кандидата.

**Поведение:** первый вход открывает задачи найма. Выбор вакансии открывает ее текущий рабочий этап и сохраняет выбранную задачу в адресе. Активная вакансия выделена постоянно; переходы между кандидатами не сбрасывают выбор. Группа задач сворачивается отдельной кнопкой. У строки вакансии одна функция, переход; раскрывающая стрелка, если нужна, является отдельной кнопкой. Завершенные задачи доступны через «Архив», без длинного дерева вложенности.

**Готовая основа:** [shadcn sidebar-07, AppSidebar](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/blocks/sidebar-07/components/app-sidebar.tsx) и [NavMain](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/blocks/sidebar-07/components/nav-main.tsx). Проверено в исходнике: `collapsible="icon"`, `SidebarHeader/Content/Footer/Rail`, группы через Collapsible. Демо содержит много посторонних групп, которые для HR Vision не нужны.

**Клавиатура и телефон:** навигационные ссылки доступны через Tab, активная получает `aria-current="page"`; кнопка раскрытия работает через Enter/Space по [Radix Collapsible](https://www.radix-ui.com/primitives/docs/components/collapsible). На узком экране колонка становится модальным листом по кнопке «Меню». После выбора лист закрывается и фокус переводится к заголовку открытой страницы; при отмене возвращается к кнопке меню. Лист использует Radix Dialog, а не вручную имитируемое перекрытие.

**Наша адаптация:** ширина около 15rem, строки около 44 CSS px, светлая нейтральная поверхность, фиолетовый только у активного пункта и главного действия. Сворачивание всей колонки необязательно: подписи по умолчанию полезнее экономии нескольких сантиметров.

**Выбирать, если:** пользователь переключает несколько вакансий и должен всегда понимать, в какой задаче работает. Это наиболее спокойный и узнаваемый базовый вариант.

## Б. Узкий рельс + контекстная очередь

**Скелет:** три области: постоянный рельс с разделами, контекстный список, рабочий документ. На рельсе «Задачи», «Решения», «Встречи». Вторая колонка показывает вакансии, ожидающие решения карточки или встречи выбранного дня. Справа открывается конкретная задача/кандидат. Название вакансии всегда видно над содержимым кандидата.

**Поведение:** выбор иконки меняет содержимое второй колонки и раскрывает ее. Выбор элемента очереди меняет только правую область. Повторный клик по текущей иконке ничего не закрывает; для скрытия колонки есть отдельная явная кнопка. После оценки текущая карточка обновляет статус; автоматическое исчезновение и перескок фокуса на другого человека не обязательны. Переход к следующему кандидату задается явным действием. Задача найма остается начальным разделом.

**Готовая основа:** [shadcn sidebar-09, AppSidebar](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/blocks/sidebar-09/components/app-sidebar.tsx). Проверено: вложенные панели, первая фиксирована до ширины иконок, вторая заполняет оставшуюся ширину; клик выбирает раздел и вызывает `setOpen(true)`. Это существенно ближе к рабочему разбору очереди, чем простой sidebar-07.

**Ограничение готового примера:** sidebar-09 является почтовым демо. В обработчике есть случайная сортировка/подвыборка писем, а вторая панель скрывается через `hidden ... md:flex`. Эту логику не переносить; мобильный список нужно спроектировать отдельно.

**Клавиатура и телефон:** у каждой иконки есть доступное имя и Tooltip на hover/focus. Tooltip дополняет имя, не заменяет его. Порядок Tab идет от рельса к списку, затем к документу. На телефоне это последовательные экраны «список → карточка» с видимой кнопкой назад, а не три сжатые колонки. Три основных раздела можно разместить в нижней полосе с текстовыми подписями. Сохранять выбранный элемент и позицию списка при возвращении.

**Наша адаптация:** рельс 64 CSS px, контекстный список около 280 CSS px; в узком desktop-окне вторая колонка скрывается явным контролом. Фиолетовое заполнение только у выбранной иконки, белая рабочая область. Иконки Lucide: BriefcaseBusiness, ListTodo, CalendarDays; подписи остаются обязательны для доступности.

**Выбирать, если:** основной режим работы это много последовательных решений по кандидатам. Цена варианта: больше состояний и хуже первичная понятность одних иконок.

## В. Верхняя навигация + локальный маршрут задачи

**Скелет:** одна горизонтальная полоса «Задачи найма · Требуют решения · Встречи», профиль справа. Под ней заголовок выбранной задачи, краткий статус и следующий доступный шаг. Полная ширина ниже отдана кандидату, оценке или сравнению. Постоянного бокового меню нет.

**Поведение:** «Задачи найма» открывает список. Внутри задачи виден путь возврата и, при наличии содержимого, локальные ссылки «Кандидаты», «Встречи», «Решение». Будущие этапы не изображаются активными вкладками. Переход между глобальными разделами сохраняет контекст задачи через адрес; браузерная кнопка назад работает ожидаемо. Не нужен раскрывающийся мегаменю для трех ссылок.

**Готовая основа:** [Radix Navigation Menu](https://www.radix-ui.com/primitives/docs/components/navigation-menu) и [shadcn Radix Navigation Menu](https://ui.shadcn.com/docs/components/radix/navigation-menu). Проверены `NavigationMenu.Root/List/Item/Link`, `Link asChild active={...}`. Это навигация, а не ARIA menubar. Пример Next.js служит демонстрацией композиции; HR Vision не требует Next.js для этого паттерна.

**Клавиатура и телефон:** все переходы являются ссылками. Radix поддерживает Tab, стрелки и Home/End, а для раскрываемых групп Enter/Space и Escape; на трех прямых ссылках раскрываемые группы не нужны. Если используются локальные Tabs, они переключают соседние панели одной задачи, а не подменяют всю навигацию. На телефоне три глобальных ссылки переходят в нижнюю полосу с теми же названиями; профиль остается в шапке. В самой задаче локальные ссылки можно заменить одной кнопкой выбора раздела в Dialog. Не оставлять важные пункты за невидимым горизонтальным скроллом.

**Наша адаптация:** шапка около 64 CSS px, сдержанная линия выбранного пункта либо бледно-фиолетовая подложка. Логотип не занимает отдельный большой блок. «Создать задачу» находится на экране задач; «Оценить кандидата» рядом с кандидатом. На мобильном контент получает нижний отступ под панель и safe area.

**Выбирать, если:** у работодателя немного задач, визиты нерегулярны, а основная ценность в широком содержимом. Цена варианта: перечень вакансий не виден постоянно, переключение между ними требует дополнительного перехода.

## Общее поведение и граница заимствования

| Что берем готовым | Что остается нашим решением |
|---|---|
| Radix: клавиатурное поведение, Dialog focus trap/возврат фокуса, Collapsible state, Tooltip | Состав разделов, названия, связь с задачей, условия доступности этапов |
| shadcn: композицию панелей, отдельные desktop/mobile состояния, стиль активного пункта | Размеры, оттенки HR Vision, мобильную информационную структуру |
| Motion: `MotionConfig reducedMotion="user"`, `useReducedMotion` | Когда движение полезно, длительность и характер перехода |

Для модального меню [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) дает удержание фокуса и закрытие по Escape; нужны доступный Title, явная кнопка закрытия и правильное управление фокусом при переходе на новую страницу. Для меню со ссылками подходит семантический `nav`; W3C отдельно поясняет, почему обычную навигацию не следует превращать в [ARIA menu/menubar](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/).

Исходный shadcn Sidebar регистрирует глобальный Cmd/Ctrl+B без проверки поля ввода. Для HR Vision этот shortcut стоит либо убрать, либо разрешать только вне input/textarea/contenteditable; видимая кнопка сворачивания остается. Cookie в исходнике лишь записывает состояние; восстановление требует отдельного чтения. Это замечания по прочитанному [исходнику Sidebar](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/sidebar.tsx), не проверка работающего меню HR Vision.

Фиолетовый должен обозначать выбор и главное действие, а иерархия строиться отступами, расположением и типографикой. Apple в [WWDC25, Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/) рекомендует группировать элементы по функции/частоте, сохранять структуру при смене устройства, использовать подпись при неоднозначном символе и отделять постоянную навигацию от действий конкретного экрана. Размеры и бело-фиолетовая палитра выше являются нашей веб-адаптацией, не стандартом Apple; стекло здесь не требуется.

Переходы должны сразу реагировать на ввод. Для раскрытия небольших групп достаточно короткого изменения высоты/прозрачности; большая панель не должна подпрыгивать. При reduced motion отключать перемещение, сохраняя изменение состояния; Motion документирует это в [React accessibility](https://motion.dev/docs/react-accessibility). API доступны в установленном стеке, но интеграция и поведение в браузере в рамках этого исследования не тестировались.

Минимальная приемка будущего прототипа: 1440/1024/390 CSS px; длинное название вакансии; 200% масштаб; полный путь клавиатурой; Esc и возврат фокуса; пустой список/несколько вакансий/длинная очередь; сохранение задачи и позиции при возвращении; отсутствие горизонтального переполнения и потери доступа к разделам.
