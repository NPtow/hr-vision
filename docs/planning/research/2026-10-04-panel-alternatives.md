# 10 вариантов просмотра подборки

Дата: 4 октября 2026. Статус: интерактивные варианты для выбора, не согласованный интерфейс продукта.

## Границы

Исследуем, как нанимающий просматривает трёх кандидатов внутри выбранной задачи. Общее направление: минимум навигации, задача найма прежде подборки, без глобального сайдбара. В галерее первоначально открыта сама подборка; «Задачи найма» возвращает к выбору задачи, из которого можно снова открыть подборку.

Один вариант показан в каждый момент. Переключатель 01–10 и стрелки принадлежат оболочке лаборатории. Данные во всех вариантах одинаковые: существующие вымышленные Анна Миронова, Михаил Белов и Елена Орлова из `interface-lab/src/scenes/agency-product/model.ts`. Дополнительные достижения, оценки, рейтинги, результаты проверок и реальные записи не придуманы. Цитата открывается как текстовый фрагмент с указанием источника и демонстрационной природы.

Последующее решение по найму, согласование встречи, фидбэк после интервью, оценка интервью, оффер, обмен сообщениями и бэкенд в эти варианты не входят. Последнее уточнение пользователя относится к фидбэку после интервью и оценке интервью, а не к видеоотказу. Галерея не реализует ни один из этих ещё не согласованных процессов.

## Что проверяем выбором варианта

| № | Вариант | Изменение структуры или взаимодействия | Цена подхода |
|---|---|---|---|
| 01 | Список и профиль | Постоянный список слева, выбранный профиль справа; на телефоне отдельный экран с возвратом | Делит внимание между двумя областями |
| 02 | Таблица и панель | Компактное сравнение условий; профиль открывается в боковом модальном окне | Дополнительное действие для подробностей |
| 03 | Раскрывающиеся строки | Один профиль раскрывается на месте, остальные кандидаты остаются строками | Длинное раскрытие сдвигает следующих людей |
| 04 | Карточки и погружение | Три кратких портрета; выбор заменяет подборку самостоятельным профилем | Для смены кандидата нужен возврат |
| 05 | По одному | Один человек в центре; очередь управляется стрелками и аватарами | Сравнение опирается на память |
| 06 | Досье | Связный документ; условия и история в полях, объяснение и основания в тексте | Меньше сведений видно за один экран |
| 07 | Сравнение по строкам | Единая матрица: один критерий сразу по всем людям | На узком экране нужна горизонтальная прокрутка |
| 08 | Сначала свидетельства | Основная навигация состоит из кейсов интервью, человек раскрывается из кейса | Личное резюме оказывается вторичным |
| 09 | Лента профилей | Полные профили рядом в горизонтальной ленте со scroll snap и кнопками | Соседние профили видны частично |
| 10 | Через задачу | Сначала общий вопрос: релевантный опыт, неизвестное или условия; затем ответы всех кандидатов | Цельный портрет собирается из нескольких частей |

Различия являются авторскими вариантами организации информации. Это не десять готовых дизайнов, найденных в библиотеках, и не утверждение, что один вариант уже лучше остальных. Цвета, шрифт, сущности и формулировки сохранены общими для содержательного сравнения.

## Context7: фактический поиск и чтение документации

Использован локальный CLI из skill `context7`: `/Users/NIKITA/.codex/skills/context7/c7`. Исследование выполнено отдельным агентом с явной последовательностью `search`, затем `docs` по возвращённым ID. Ключ и конфигурация в проект не переносились.

Поиск:

```text

```

Найденные ID: `/shadcn-ui/ui`, `/websites/ui_shadcn`, `/radix-ui/primitives`, `/websites/radix-ui_primitives`. Для чтения использовались `/shadcn-ui/ui` и `/websites/radix-ui_primitives`.

```text

```

Проверенные первичные источники:

- [shadcn Sheet, ветка Radix](https://ui.shadcn.com/docs/components/radix/sheet): композиция панели с заголовком, описанием, содержимым и действиями. Вариант 02 использует существующий Radix Dialog с нашим боковым CSS-положением; новый компонент Sheet не устанавливался.
- [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog): доступные Title и Description, модальность, Escape, управление фокусом. В коде храним реальный открывший элемент перед открытием и возвращаем на него фокус при закрытии.
- [Radix Accordion](https://www.radix-ui.com/primitives/docs/components/accordion): Root, Item, Header, Trigger и Content; режим `type="single"` с `collapsible`. Вариант 03 позволяет закрыть и последнюю открытую строку.
- [Radix Tabs](https://www.radix-ui.com/primitives/docs/components/tabs): список, триггеры и соответствующие панели с управлением выбранным значением. Используется для трёх тематических разделов варианта 10. Переключение людей, где нет отдельных tabpanel, реализовано обычной группой кнопок с `aria-pressed`.
- [shadcn Table, ветка Radix](https://ui.shadcn.com/docs/components/radix/table): семантическая структура таблицы. В вариантах 02 и 07 используются нативные `table`, `caption`, `thead`, `tbody`, `th`, `td`; дополнительные зависимости таблиц не нужны.
- [shadcn Item, ветка Radix](https://ui.shadcn.com/docs/components/radix/item): композиция аватара, заголовка, описания и действий; источник для структуры элементов, не готовый дизайн HR-панели.

Важное ограничение текущей выдачи: общие ссылки shadcn `components/sheet` и `components/table` перенаправлялись в Base UI. Context7 возвращает фрагменты из веток Base, Radix и Aria. Поэтому ветка первичного источника проверялась явно. API Base Accordion с `multiple` и массивом `defaultValue` не переносился в Radix.

Сверка существующего стека: React 19.3.0, Storybook 10.6.1, radix-ui ^1.6.7, существующие компоненты shadcn new-york-v4 и Inter. Пакеты не добавлялись. Переиспользован существующий Button, остальные интерактивные примитивы импортированы из уже установленного `radix-ui`.

## Геометрия и визуальная дисциплина

Прочитаны skill `apple-design` и оба его reference: `geometry-and-layout.md`, `apple-primary-sources.md`. Первичный доклад [Get to know the new design system, WWDC25](https://developer.apple.com/videos/play/wwdc2025/356/) дополнительно открыт и проверен по транскрипту. Использованы опубликованные принципы: группировать связанные элементы, выражать иерархию компоновкой, согласовывать вложенные формы и отступы, учитывать оптический баланс. Страница [HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout) в текстовом просмотре требовала JavaScript; её конкретное содержимое не представлено как проверенное этим просмотром.

Численные отступы, радиусы, плотность, сетки и бело-фиолетовая палитра являются решениями этого веб-макета. Они не названы универсальной сеткой или закрытой формулой Apple. Сохраняются доступный контраст, явные состояния выбора и фокуса, переносы на узком экране, reduced motion. У ленты есть кнопки как альтернатива прокрутке жестом.
