# Кандидат после интервью — уточнённый сценарий

26 октября 2026. Текущая версия: V2 по замечанию пользователя. Сохраняем минимальный путь после первого разговора с рекрутером. Пароль в письме, отдельный экран регистрации и кнопка «Завершить регистрацию» исключены из нового макета.

## Три входа

| Состояние после завершения встречи | Что видит кандидат | Действие и результат |
| --- | --- | --- |
| Кабинета нет, контактная почта уже есть | «Встреча завершилась», адрес отправленного письма | Открывает письмо → «Открыть кабинет» → авторизация по одноразовой ссылке → онбординг |
| Кабинета нет, почты нет | «Встреча завершилась» и поле почты | Вводит адрес → получает то же письмо → кнопка авторизует и открывает онбординг |
| Зарегистрирован до интервью, профиль проверен | Кабинет: «Встреча завершилась. Новые вакансии будут появляться здесь» | Может изучить пример вакансии и по желанию подключить Telegram; повторный онбординг не нужен |

Онбординг после ссылки: проверка подготовленного профиля и условий поиска → явное согласие на использование материалов → кабинет ожидания. Уже загруженные резюме и интервью остаются у того же кандидата. Согласие не проставляется за человека и не заменяется фактом перехода по ссылке.

«Почты нет» в этом сценарии означает, что у сервиса ещё нет контактного адреса кандидата. После его ввода подтверждение владения адресом происходит переходом из письма. Сохранённый контакт, подтверждённая почта и активная сессия — разные состояния. Аккаунт другого человека с совпавшей почтой не объединяется автоматически.

## Кабинет и Telegram

- Пример вакансии помечен как пример, не попадает в реальные applications, не отправляет приглашения и не учитывается ядром.
- Кандидат может раскрыть пример, нажать «Мне интересно / Не подходит» и увидеть пояснение результата без реальной отправки.
- Telegram необязательный. Подпрыгивает только иконка рядом с «Подключить Telegram»: три коротких цикла. `prefers-reduced-motion` отключает движение.
- В макете подключение бота имитируется отдельным экраном и кнопкой «Запустить»; после возвращения показано подключение.
- Локальный выход из звонка не означает серверное завершение. В макете это отдельное состояние с возвратом в разговор.

## Реализация для production

Реализация V3 подготовлена 26 октября в `codex/candidate-completion-flow`, поверх `origin/main` 7e826d0b. Она заменяет первоначальную выдачу пароля в продолжении звонка одноразовой ссылкой. Старый вход с паролем и старые приглашения остаются совместимыми.

- `candidate_access.py`: отдельная очередь `cp_email_access`, автоматическая постановка после канонического `interview.completed`, ввод отсутствующей почты только по действующей ссылке завершённого звонка, одноразовое погашение за 24 часа и повторный запрос истёкшей ссылки. Известную почту нельзя заменить через гостевой интерфейс. Конфликтующие профили не объединяются.
- Токен в fragment URL, убирается до обмена на HttpOnly session cookie. В БД хранится hash; аккаунт активируется только после перехода из письма. Consent и autoApprove этим действием не включаются.
- SMTP: HTML-кнопка и текстовая версия; неизвестный результат доставки не повторяется автоматически. Ответ запроса ссылки не раскрывает наличие аккаунта.
- Профиль: отдельное CV с существующим popup-просмотром; обязательные должность, зарплата от, локация, занятость, формат работы, компании либо «Не важно». Поля даты выхода и верхней зарплаты в форме отсутствуют. Сохранение формы очищает верхний предел. Старые проверенные профили не принуждаются к повторному онбордингу.
- Минимальное явное согласие; после него настоящая `ApplicationCard` с примером. Пример не пишет applications и не отправляет отклик. Telegram использует существующий bot-link API и остаётся необязательным.
- Редактирование «О себе», отзыв согласия и настройка автосогласования сохраняются в профиле.
- Семь внешних записей Zoom и их обработка ядром не меняются.

## Проверка реализации

Локально: TypeScript, 27 проверок навигации/доступа/поиска, 83 проверки приёмника, полный API-набор 1460 тестов (2 пропуска). Дополнительно добавлены проверки истечения, повтора входа без пароля, изменения email и конфликта с другим аккаунтом, сохранения минимальной зарплаты и компаний.

Computer use на локальном настоящем UI/API: кнопка HTML-письма → авторизация без пароля → CV popup → компания из примеров и собственная компания → явное согласие → настоящая карточка-пример. Внешняя SMTP-доставка и production-путь проверяются отдельно после выпуска. Успешный локальный тест не подтверждает доставку письма.

Выпуск через штатный guarded CI: backup SQLite, защита живых звонков, ровно три service entries. Для отката после создания новых ссылок/предпочтений нужен runtime с поддержкой `cp_email_access` и новых полей; старый UI не является совместимым завершением нового onboarding.
