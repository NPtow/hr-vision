# Удаление лишнего кода звонков

Режим: реализация, одобрено 25 октября 2026. Используем правила NASA из локального skill: один владелец звонка, дополнения не управляют входом/выходом, небольшой проверяемый diff.

Основной результат: кандидат, рекрутер и работодатель приходят по своим ссылкам на сайт, проходят проверку доступа и согласие, затем используют одно окно Zoom. Два допущенных участника слышат и видят друг друга; каждый может выйти. Запись и текст обрабатываются после звонка независимо от окна.

## Защищено от удаления

- Данные кандидатов, интервью, согласий, резюме, заметок, записей и транскриптов; схемы исторических идентификаторов.
- Серверная проверка приглашения/аккаунта, принадлежности встречи и роли организатора.
- Отдельное согласие на запись. Оно не заменяет согласие на дальнейшее использование профиля.
- Проверенный Zoom Client View 6.10.0, его lifecycle и выдача credentials в памяти.
- Проверка точного Zoom-сеанса: обычный Leave не означает End for All.
- Daily, существующие комнаты, материалы, конфигурация и действующий резервный путь.
- Исходники, история Git и резервные копии. Не выполняем массовое удаление файлов по названию.

## Процедура для каждого блока

1. Найти все imports, вызовы, маршруты и скрытые обязанности. Записать, что заменяет блок.
2. Подключить минимальную замену в текущих трёх сценариях. Не создавать механизмы для гипотетических провайдеров.
3. Проверить доступ/согласие, отмену и поздний ответ, повторный клик, выход, завершение и сохранность данных.
4. Удалить старое поведение и зависимости, у которых больше нет пользователей. Общий с Daily код не удалять.
5. Пройти typecheck, целевые тесты, независимое ревью причинной цепочки. Проверка настоящего звонка фиксируется отдельно от моков.
6. Выкладывать воспроизводимый небольшой релиз с сохранённой предыдущей версией. Удаление кода не подразумевает удаление данных.

## Первая партия

| Блок | Действие и причина |
|---|---|
| ZoomInterviewRoom: собственный join/abort/overlay/error | Заменить общим ZoomMeeting; оставить выбор candidate/guest API и адрес возврата |
| RecruiterZoomCall: отдельный join и call shell | Заменить общим ZoomMeeting; убрать coach/notes/resume из зависимости звонка |
| ZoomMeetingPanel: третий join/overlay/receipt/reconcile | Заменить тем же ZoomMeeting; оставить расписание и employer API |

| Гостевой экран «Подготовиться» для Zoom | Убрать промежуточное нажатие; сразу показать общее согласие |
| Недостижимый InterviewCoachPanel в DailyRecruiterCall | Удалять только после проверки всех ссылок; действующий Daily UI сохраняется |

## Серверный объём

Два прикладных блока: ядро сбора/хранения данных и Zoom API. Транскрибация принадлежит «Верстаку (2)». Не добавляем registry плагинов, авто-переключение поставщиков, новый транспорт очередей или второй планировщик ради будущих сценариев. Сохраняем уже необходимые гарантии: права, точный сеанс, ограниченные запросы, отсутствие дублей и проверка сохранённого файла.

Существующий план переключения уточняется этим документом: самостоятельный Zoom сервис нужен для текущего подключения и получения записи, а не как общий фреймворк поставщиков.
