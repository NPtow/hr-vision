# Zoom: утверждённый объём и проверка выпуска

25 октября 2026. Реализация одобрена. Этот документ заменяет ранний план с отдельным source worker/outbox: для сегодняшней задачи они не нужны.

## Что меняется

Кандидат, рекрутер и работодатель приходят по своим ссылкам на сайт. Проверки аккаунта/приглашения и роли остаются прежними. Дальше у всех один `ZoomMeeting`: отдельное согласие → штатный Zoom Client View 6.10.0 → возврат в свой кабинет. Камерой, микрофоном, демонстрацией и выходом управляет Zoom. Заметки, резюме и материалы открываются отдельно.

Новые встречи без закреплённой комнаты выбирают Zoom (`HR_CALL_PROVIDER=zoom`). Существующие комнаты сохраняют провайдера. Daily остаётся доступным как явный выбор до создания комнаты. Потерянный ответ создания Zoom не вызывает второй POST или переключение в Daily.

## Серверная цепочка

`кабинет → приватный Zoom API → Zoom`

`подтверждённое завершение встречи → ядро/существующая media_jobs → существующий worker → Zoom API → проверенный файл в S3 → нормализатор готового текста → transcript_versions → API ядра → кабинет`

- **Zoom API**, 127.0.0.1:8095: создание встречи, доступ, состояние, получение точного файла. OAuth и SDK-секреты остаются здесь. Нет своей БД, очереди, worker или scheduler.
- **Ядро**, 127.0.0.1:8093: связи кандидата/интервью/материалов, сбор через существующий worker, досье, версии текста, выдача доступа. `POST /v1/owners/{kind}/{id}/collect` получает только идентификатор владельца; комнату берёт из HR БД. Сохранённая завершённая встреча позволяет восстановить пропущенное задание фоновым backfill.
- **Нормализатор «Верстак (2)»**, 127.0.0.1:8094: существующий `POST /v1/normalize` получает исходные VTT/SRT/JSON. Исходный файл уже лежит в нашем S3. ASR не выбирается и не запускается.
- Работает прежняя очередь RabbitMQ `materials`, прежние worker/scheduler и прежние material IDs. Второй конвейер для Zoom не создаётся.

Видео Zoom в этом выпуске копируется в наш S3. Оба режима хранения сохранены в системе: исторический Daily может оставаться ссылкой или собственной копией. Текст всегда сохраняется у нас. Автоматическое удаление записей у Zoom выключено.

## Что удалено и что защищено

Три отдельных реализации Zoom join/overlay/abort заменены одним компонентом. Убраны предварительный экран подготовки гостя Zoom, зависимость звонка рекрутера от coach/резюме/заметок, недостижимый `InterviewCoachPanel` и его недостижимые controls. Действующий Daily UI, заметки, согласия, приглашения и данные сохранены. Процедура и перечень — `code-removal-procedure.md`.

## Проверка перед переключением

- TypeScript и production-сборка.
- 34 браузерных теста трёх входов: согласие, поздний ответ, отмена, роли, выход, отдельные заметки, недоступный coach.
- 1 315 серверных тестов, 2 штатных пропуска; 70 тестов приёмника релизов.
- 31 тест ядра, 12 Zoom API, 8 упаковки, 1 сквозной HTTP-тест core/Zoom/normalizer с локальными provider/S3 фикстурами.
- Независимый обзор default/create race, owner/auth, сохранности legacy IDs, границ секретов, ограничений загрузки и очистки временных файлов.
- На сервере: приватные порты, минимальные окружения, backup SQLite, существующий S3/Rabbit, чтение настоящей сохранённой 77-секундной записи и исходного текста через новые API.

## Приёмка настоящего разговора после 12:00 МСК

Два человека входят по своим ссылкам, соглашаются на запись, слышат и видят друг друга. Обычный Leave выводит одного участника; End for All завершает встречу. В кабинет возвращаются без ожидания S3/нормализации. Запись появляется у правильного кандидата и читается из нашего S3; текст либо сохранён, либо показано его фактическое ожидание. Отдельно проверяются вход работодателя и готовность следующего разговора.

Автоматические тесты и повторное чтение прежней записи не заменяют этот живой разговор. При выпуске сохраняются точные версии UI/API/services и предыдущие указатели; БД автоматически назад не восстанавливается. Откат default касается только ещё не закреплённых встреч.
