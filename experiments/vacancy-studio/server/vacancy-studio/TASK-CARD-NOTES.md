# Выбор задачи вместо числового уровня

Запрос 26 октября 2026: работодатель выбирает ожидаемую работу, затем важность; оценки, цитаты, уверенность и повторные сообщения из карточки удаляются. Принятый навык остаётся только в профиле. Черновики и факты сохраняются.

## Реализация

- `TaskSkillCard.tsx`: одна поверхность, сначала четыре варианта работы, затем важность. Числа L2–L5 остаются только в данных. Передача в API использует выбранный уровень и importance 1–3. Сначала сохраняются изменения, затем принимается предложение с новой серверной revision; ошибка не изображается успешным добавлением.
- `task-templates.json` + `task-options.ts`: 64 отдельные рабочие формулировки для 16 навыков. Это резерв для старых черновиков, ответов без новых сценариев и обнаруженных формулировок вроде «не связывать сведения с решением». Для вакансий с пригодными `task_scenarios` используются сформированные Gemini варианты. Переключение вариантов не вызывает модель.
- `prompts/task-scenarios.md`: дополнение к существующему compose, четыре коротких варианта только для предложенных навыков. Подтверждённый контекст берётся из полного корпуса. Дополнительных вызовов на каждый навык нет.
- `task_scenarios.py`: схема, проверка полноты/различий и генератор инструкций для всех 80 пар «навык × уровень». Семантическую корректность текста проверка формата не доказывает.
- `output/vacancy-task-cards-20261026/level-prompts.json`: 80 индивидуальных инструкций с точными исходными якорями и версией каталога.

L1 исходной шкалы означает проблемное поведение, а не работу начинающего с поддержкой. Он не превращён в «junior» и не изменён в ядре. 16 таких якорей сохранены в инструкциях с запретом предлагать их как нормальную задачу. Если старый профиль имеет L1, интерфейс требует явного выбора задачи, не меняя значение сам.

Анимация заимствована из `interface-lab/src/scenes/candidate-portal/CandidateSearch.tsx`: расширение самой карточки через layout spring 380/38/0.8, появление содержимого .18s/.08s. Учитывается reduced motion. Пиксели и анимация в браузере после правки не проверены: автоматизация браузера недоступна.

## Основания для решения

[O*NET — Scales, Ratings, and Standardized Scores](https://www.onetonline.org/help/online/scales): важность и требуемый уровень различаются, а примеры поведения привязаны к конкретному навыку. Отсюда берём раздельный выбор задачи и важности, но не заимствуем числовые шкалы O*NET.

[USDS SME-QA — Defining Proficiency Levels](https://smeqa.usds.gov/hiring-phases/job-analysis/defining-proficiency-levels/): различать требования можно по сложности, подробности, масштабу и самостоятельности работы. Наши тексты являются продуктовой адаптацией текущих якорей, а не независимо валидированной методикой оценки.

## Проверка и выпуск

- TypeScript, сборка отдельной истории, 20 сценариев DOM (mock API) и 51 серверный тест вместе с 8 тестами сценариев.
- DOM: отсутствие оценок и повторных блоков, два шага, точное сохранение уровня, новая revision при принятии, редактирование на месте, восстановление, отказ сохранения, старый L1 и новые Gemini-тексты.
- Рабочий API версии 2026-10-26.4 вернул `task_scenarios`; через него проверено сохранение выбранных L4 и importance=1 с исходной цитатой и сценариями после повторного чтения. Это отдельная синтетическая сессия; пользовательский черновик не менялся. Отчёт: `live-scenarios.json`.
- На этом прогоне модель выдала плохую формулировку L2. UI теперь использует подготовленный набор вместо таких формулировок. В дополнение к prompt добавлены положительные рабочие шаблоны в каталог. Последний отдельный прогон нового кода на настоящем Gemini: 4,79 с, один запрос, четыре корректно различающихся варианта A03; это единичный замер, а не гарантия задержки. Отчёт: `provider-scenarios-final.json`.
- Боковая ветка не перезапускает процесс основного треда. Последнее дополнение рабочего каталога шаблонами загрузится при штатном следующем запуске сервера. UI опубликован отдельно, без сброса пользовательской сессии; корректный резервный набор доступен уже сейчас. Изображение после правки не проверено в браузере.
