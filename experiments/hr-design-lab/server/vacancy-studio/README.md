# HR Vision — рабочий макет создания вакансии

Локальный эксперимент по выбранным Никитой референсам. Начальный ввод и пять живых отметок — по механике Metaview; раскрываемый профиль — развитие нашего «Портрета из блоков», с композицией HubSpot. Светлые поверхности и спокойные цветовые категории МашаДаша. Существующий Pulse и рабочие вакансии не меняются.

## Открыть

http://127.0.0.1:4321/iframe.html?id=hr-vision-vacancy-studio--live&viewMode=story

В общей лаборатории также есть история `hr-vision-vacancy-studio--live` на порту 6006. Отдельная сборка включает только эту историю, чтобы параллельная работа над другими сценами не ломала макет.

1. Написать описание, прикрепить PDF/DOCX/текст, надиктовать или добавить ссылку.
2. Отметки пяти тем меняются сразу в браузере. Это индикатор упоминаний, а не извлечённые и принятые требования.
3. После отправки Gemini одним ответом извлекает факты и предлагает навыки. Сервер проверяет структуру и цитаты, затем выбирает вопрос о конкретном навыке или условии.
4. Раскрыть предложение прямо в чате, выбрать ожидаемую рабочую задачу и её важность. Исходные цитаты сохраняются в данных.
5. Факты автоматически становятся редактируемым описанием вакансии сверху; «Добавить» переносит навык в карточки ниже. Явно обязательные условия отмечены отдельно, обычные факты не включают жёсткий фильтр.
6. Профиль раскрывается в широкий лист. Подтверждение сохраняет черновик; можно скачать читаемый Markdown. Публикации в Верстак пока нет.
7. Кнопка настройки справа сверху переключает карточки: цвета по смыслу / лаванда / нейтральные.

## Реальные подключения и границы

- `gemini-3.5-flash-lite` с `reasoning_effort: minimal` через существующий локальный CLIProxyAPI. Один вызов compose возвращает извлечение и подтверждённые темы навыков; затем validate выполняет локальные проверки, а `interview.py` выбирает вопрос. Инструкция `prompts/compose.md`, версия `2026-10-26.6`. Готовый вариант ответа обрабатывается без модели.
- Каталог: 16 параметров, 80 индивидуальных поведенческих описаний, версия `2026-10-26.behavioral-anchors.1`. Используется тот же закреплённый JSON, что в исследовании ядра. Динамической синхронизации каталога с production API в этом эксперименте нет.
- Уровни 1–5; важность принятого навыка 1–3. «Не добавлять» исключает параметр. Confidence — качественная интерпретация модели, не калиброванная вероятность и не оценка кандидата.
- Голос: MediaRecorder → Deepgram Nova-3, русский, до двух минут/5 МБ. Запись только по нажатию; результат попадает в редактируемый ввод. Отправка текста отдельным действием. Аудио хранится только в памяти запроса.
- Файлы: текстовые PDF до 60 страниц, DOCX, UTF-8 TXT/MD/CSV до 5 МБ и 60 000 символов. Скан без текста требует вставить текст. До 4 источников на ответ. Данные не обрезаются молча.
- Ссылки: открытые HTTPS-страницы. Закрытые/динамические страницы, редиректы и антибот могут потребовать скопировать текст. Адрес проверяется и закрепляется на публичном IP; внутренние адреса запрещены. Для локального VPN fake-DNS предусмотрено повторное разрешение через фиксированный Cloudflare DoH с повторной проверкой публичности IP. [Документация протокола](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/).
- Нет поиска/рассылки кандидатам, публикации вакансии или изменений production-ядра. Подтверждение касается этого локального черновика.

## Запуск

Из `/Users/NIKITA/Downloads/proteus-storybook`:

```sh
npx tsc --noEmit -p server/vacancy-studio/tsconfig.json
npx storybook build --config-dir server/vacancy-studio/storybook --output-dir output/vacancy-studio-20261026/storybook --disable-telemetry
python3 server/vacancy-studio/run.py --pulse-voice
```

`run.py` читает существующий локальный ключ CPA в память. `--pulse-voice` получает уже используемый Pulse ключ распознавания по проверенному SSH-соединению; не пишет его в файлы и не изменяет удалённый сервис. Без этого флага можно передать `DEEPGRAM_API_KEY` окружением. Модель переопределяется `STUDIO_MODEL`, усилие — `STUDIO_REASONING_EFFORT`. Оба значения участвуют в ключе кеша, метаданных задания и health endpoint. Старый `STUDIO_JUDGE_MODEL` больше не участвует в обработке хода.

Сервис слушает только `127.0.0.1:4321`. Данные — отдельный SQLite `output/vacancy-studio-20261026/state.sqlite3`, права 600, каталог 700. Идентификатор сессии — случайная capability; хранится в localStorage, не в URL. История и очередь сохраняются до ответа API. Перезапуск переводит незавершённый запрос в повторяемую ошибку. Бюджет — 40 ходов/150 model calls и 60 голосовых записей на сессию.

Проверки схем/цитат/правил обязательности выполняются до сохранения предложений. Некорректный JSON получает одну попытку исправления. Провал проверки не порождает подставной успешный ответ. Отдельной семантической проверки второй моделью теперь нет: локальный валидатор проверяет структуру, принадлежность источников, точность цитат, каталог и правила обязательности, но не доказывает смысловую верность всех формулировок. Новые сведения могут заменить непринятое предложение, сохраняя старую цитату в истории; ручные изменения и принятые требования защищены.

## Автоматический контекст вакансии

`vacancy_context` — серверная проекция принятых фактов по ключам; она не хранится как второй изменяемый профиль. После проверки извлечённые факты автоматически принимаются с `automatic=true`, но эффективный `hard_filter=false`. Предложение модели об обязательности остаётся в `original.hard_filter` и `suggested_hard_filter`. Включить фильтр можно явным редактированием или прямым ответом на вопрос об этом условии. `requirement_status` различает `unknown`, `required`, `preferred`: неуточнённое не означает необязательное. Отрасль компании и роль фильтрами не становятся. Навыки требуют явного принятия.

Новый дословный источник может уточнить только автоматический факт; прежняя версия с цитатой сохраняется как `superseded`. Ручные правки и ранее явно принятые факты защищены. При первом чтении старого черновика локальная версия нормализации 1 переводит сохранённые pending-факты без ручных правок в автоматический контекст, выключая фильтр; принятые, отклонённые и исторические предложения сохраняются. Повторное чтение ничего не меняет и не вызывает модель.

Очередь и реальные этапы compose/validate/repair содержат epoch-ms `started_at`, `updated_at`, `phase_started_at`, `attempt_started_at`. `repair` выставляется перед вторым запросом после ошибки проверки. Повтор задания сохраняет начало исходного задания и отмечает начало попытки. Старые задания без времён не получают выдуманного начала.


## Задержка ответа — версия 2026-10-26.3

Последовательность `extract → interview → judge` заменена на `compose → validate`: один структурированный ответ Gemini содержит `extraction` и `reply`. На успешном ходе выполняется один вызов вместо трёх. Полный корпус источников, полный каталог и история принятых/отклонённых предложений передаются без молчаливого обрезания. Это сокращает число сетевых ожиданий; фактическое время зависит от CPA и модели и не обещается заранее.

`validate` — реальные локальные проверки JSON-схемы, точной цитаты в принадлежащем сессии источнике, ID и уровня каталога, дублей и обязательности фильтров. Это не независимый LLM judge. При неверном выводе разрешено ровно одно исправление той же моделью; второй неверный ответ завершает задание ошибкой. Сетевой сбой не запускает скрытый каскад моделей. Лимиты вызовов, таймаут, durable jobs, повтор задания и защита ручного/принятого контекста сохраняются. Старые сохранённые задания и исторические артефакты приёмки могут содержать прежние названия этапов.

На фиксированном синтетическом запросе `gemini-3.5-flash-lite` с явно заданным `minimal` вернул валидную композицию за 5,783 с. Без явной настройки тот же составной запрос занимал 30,624 с; это отдельные измерения, не SLA. Старый полный путь в живом сервисе занимал 48,22 с. Сырые замеры и итог полного API-пути: `output/vacancy-studio-20261026/latency/`. CPA переводит `reasoning_effort` в `thinkingLevel`; minimal не означает полного отключения размышления.

Версия .4 добавляет безопасный код ошибки валидации и адресное исправление предыдущего JSON. Обычные упоминания места, формата работы и опыта явно не требуют включать фильтр. Архив прежнего основного промпта — `prompts/archive/compose-2026-10-26.3.md`.

Полный HTTP-путь версии .4 на том же синтетическом описании SDR занял **6,16 с**, один вызов провайдера: 6 фактов автоматически, A03/L3 предложен работодателю. Точность цитат, повторная отправка без нового вызова, повторное чтение и сохранность семи прежних черновиков проверены. Артефакт — `latency/live-v4-verification.json`. Это отдельный замер; более ранний прогон .3 с исправлением ответа занял 36,22 с и сохранён в `latency/live-v3-verification.json`.

Актуальная проверка бэка .4: **43 алгоритмических теста**. Они проверяют один запрос на корректный ход, максимум одно исправление, отказ при выдуманной цитате, весь корпус, автоматические факты, сохранность ручных правок, приватность диагностики и отдельный кеш для разных настроек reasoning. Для опубликованной сборки интерфейса до параллельной переделки TaskSkillCard прошли 16 DOM-сценариев, TypeScript и Storybook build. Хеши реально выдаваемых JS/CSS — `latency/served-frontend.json`; это не визуальная проверка браузером.

Исследование подключения к ядру, текущие ограничения его API и предложенный контракт подтверждённого профиля: [CORE-INTEGRATION.md](CORE-INTEGRATION.md). Это проект интеграции; подтверждение в данном макете пока не публикует вакансию в Верстак.

## Вопросы по требованиям — версия 2026-10-26.6

`interview.py` владеет выбором вопросов и эффектами ответов. Модель больше не выдаёт произвольные `question/options`. `planning.skill_topics` содержит только параметры каталога с цитатой о работе; для неподтверждённой задачи задаётся вопрос с четырьмя рабочими вариантами из закреплённых шаблонов L2–L5. Уже принятые, предложенные карточкой и отклонённые навыки повторно не опрашиваются. Остальные навыки не добавляются в анкету лишь из-за названия роли.

После навыков уточняются опыт, опыт в отрасли, локация, формат работы и занятость. Сначала значение, затем отдельное решение — исключает ли отсутствие этого условия кандидата. Свободный ответ привязан к исходному вопросу в `in_reply_to`; связь сохраняется во всём корпусе, а не только в последних восьми сообщениях. `planning.conditions` по схеме допускает максимум одно решение только для условия текущего вопроса; до такого вопроса массив обязан быть пустым.

Выбор готового варианта передаёт ID вопроса и индекс варианта. Сервер сверяет их с выданными им вариантами, применяет эффект без модели и сохраняет ответ вместе с вопросом. Выбранная рабочая задача создаёт pending-навык: важность 2 — начальное предложение, которое работодатель подтверждает/меняет в карточке. Выбор задачи защищён от замены моделью. «Добавить» по-прежнему требуется отдельно. Повтор отправки идемпотентен; старый вопрос и подмена текста варианта отвергаются. Неотправленный текст и файлы не стираются при выборе варианта.

«Пока не знаю» не создаёт фактов и не выключает фильтр. Каждый выявленный пробел спрашивается один раз; неуточнённые пункты перечислены в `interview_progress.unresolved`. После обхода выявленных навыков и условий вопросы заканчиваются, но профиль не становится автоматически подтверждённым. Количества лидов, SLA ответа и нынешние способы контроля не используются для подмены уровня навыка.

Миграция старого открытого диалога сохраняет все старые сообщения и решения, добавляя один новый вопрос с явной целью. Модель при чтении не вызывается. Продолжающийся запрос не мигрируется до завершения. Отдельно сохраняется прежняя миграция контекста версии 1.

Проверки этой версии: `test_interview.py`, полный offline suite, `output/vacancy-studio-20261026/verify-targeted-ui.mjs`, `verify-targeted-live.py` (синтетика, реальный провайдер, временная БД), `verify-targeted-http.py` (отдельная синтетическая сессия работающего API). Сначала отрицательный пример «Ищем SDR» выявил навыки из названия роли; добавлены отрицательный пример в промпт и проверка цитаты только из контекста. HTTP-проверка затем выявила ошибочное `preferred` из обычного упоминания условий; схема теперь ограничивает решения текущим вопросом. Это проверка конкретных сценариев, не доказательство безошибочности интерпретации любого текста.
