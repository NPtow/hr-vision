
Карточки задач (presentation-only, task-scenarios-v1):
Для каждого НОВОГО элемента skills добавь task_scenarios с ровно L2, L3, L4, L5. Это четыре варианта ОЖИДАЕМОЙ РАБОТЫ для выбора работодателем, а не извлечённые факты о вакансии или наблюдения о кандидате. Не приписывай этим текстам цитаты источника. Выбранный ключ впоследствии прямо задаёт уровень того же parameter_id; не меняй шкалу.

Для каждого ключа возьми соответствующий work_task_template из catalog как основу. Это уже описание ожидаемой работы; description — диагностический якорь для оценивания, его нельзя дословно переписывать в поручение. Уточни предмет работы из подтверждённого контекста вакансии, сохрани все смысловые действия и границы шаблона. Одна фраза с инфинитивом, 12–260 символов. Если релевантного уточнения нет, оставь work_task_template без изменения. Нельзя переносить общую шкалу одного навыка на другой. Неизвестные отрасль, CRM, KPI, число сделок, размер команды не придумывай.

L2 допускает частичную работу и поддержку там, где это следует из якоря; не изображай её полноценным самостоятельным решением. Описывай границу поручения: «собрать сведения, решение передать руководителю». Никогда не формулируй требование намеренно плохо работать: «не связывать с решением», «не проверять», «пропускать существенное» — это признаки оценки, не задания сотруднику. L3/L4/L5 различаются именно условиями и поведением своего навыка: это не универсальная последовательность «исполнитель → руководитель → директор». L1 в текущем каталоге описывает ошибку; сохрани его смысл в оценке кандидата, но НЕ предлагай его как ожидаемую работу и не называй junior.

Убери числа шкалы, junior/middle/senior, слова «плохой», «лучший», обещания качества, уверенность и пояснения о модели. Варианты должны различаться задачей, которую работодателю действительно нужно поручить. Не пиши «максимум». Например, для квалификации: «Собирать условия покупки; решение о продолжении принимает старший» отличается от «Выяснять условия покупки и самостоятельно обосновывать продолжение», а не от «Квалифицировать лучше».

Все четыре варианта — альтернативы для выбора. Текущая заявленная задача может соответствовать только одному из них: НЕ подгоняй остальные под неё. Если работодатель передаёт решение старшему, это не разрешает назвать передачу решения самостоятельной квалификацией в L3. Не добавляй отдельный вызов модели для этих формулировок. Не дублируй варианты и оценки в reply.message. Работодатель увидит задачи в карточке, затем отдельно выберет важность.
